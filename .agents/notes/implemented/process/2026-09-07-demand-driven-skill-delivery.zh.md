# Agent Note: 仅为未解决的需要增加交付流程

Status: implemented

[English](2026-09-07-demand-driven-skill-delivery.md) | 中文

## Problem

一个有界实现可能仅因引入 Provider 或 WorkKind 就进入完整交付链。即使同一 agent（智能体）保有决定和工具结果，阶段转换仍要求命名 receipt。强制模式度量与代理计划增加了记录，却没有证明它们改善了任务。正确的验证要求不足以证明这些协调成本合理。

## Decision

[Feature Delivery](../../../skills/dsh-feature-delivery/SKILL.md) 从直接工作开始。它根据实际不确定性或失败风险，补充产品澄清、复用调查、依赖规划或独立审查。技术组件名称不会选中完整流程。用户显式要求的完整流程仍具约束力；必要的权限、持久化、并发和自开发验证与协调深度分开判断。

已接受的对话决定和身份明确的工具结果可以承载任务状态，无需 receipt。[交接协议](../../../skills/dsh-feature-delivery/references/handoff-evidence.md) 为确有需要的接收方提供可选结构。未知身份不能证明新鲜度；跨会话交接保留必要的输入身份，自开发保留不可变验证计划。只有相关变化使证据失效。计划与 receipt 会重复同一事实时，一份报告就足够。

Charter 模板用于用户明确要求的或实质性多阶段产品决策。Issue DAG 用于真正有依赖的交付阶段。复用问题在决定性的本地证据足以回答时结束。聚焦文档修改保留周边结构并验证变化的声明。模式学习仅用于用户要求的比较、当前采样任务或已经开始的度量。Subagent 任务消息承载实际归属；独立工作无需代理计划说明。

本决策在强制阶段 receipt、技术关键词触发完整流程、默认度量和强制代理计划方面，部分取代[此前的交接与多代理决策](2026-08-31-dsh-skill-handoff-and-multi-agent-orchestration.zh.md)。其中的证据身份、不重叠归属、集成、中断恢复与度量结算保障仍然适用。[阶段与 checkout 决策](2026-09-07-skill-stage-distinction-and-checkout-ownership.zh.md) 继续规定范围和放置。

## Alternatives considered

**保留完整链，只标注为轻量。** 这仍保留额外产物与前序要求。直接退出路径和可选交接表示消除的是义务本身。

**连同规划一起删除高风险验证。** 协调减少不会降低数据丢失、权限越界或自证的后果。即使无需 Charter 或 DAG，也要为这些风险选择证据。

## Consequences

常规任务需要的规划和汇报动作减少；复杂任务保留其需要的协调。Agent 必须说明新增步骤解决了哪个决定或失败路径。仓库要求的文档和发布检查仍适用于实际语料。场景前向审查检查路由和保留的风险控制；真实时间与成本收益需要可比交付运行，不能仅由指令缩短证明。
