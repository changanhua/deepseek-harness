# Agent Note: 显式创意工作流

Status: implemented

[English](2026-09-15-explicit-creativity-workflow.md) | 中文

## Problem

当用户明确需要发散想法时，仓库创意工作流可以提供帮助；但自动触发的人格会覆盖范围明确的实现、评审、排障或证据任务。斜杠名称与 Skill 名称不同，还会向用户提供仓库实际不存在的调用方式。

## Decision

仓库把 `claude-creativity` 作为仅由用户手动调用的开发 Skill。其 frontmatter 禁止模型自行调用，同时保留用户调用能力；文档命令统一为 `/claude-creativity`。强度和输出样式选项只塑造用户明确要求的创意过程，不扩大工具权限、实现范围或验证结论。

该 Skill 遵循当前对话语言和更高优先级的仓库指令。只有在被调用后才加载 persona 与 technique 参考；请求任务没有有意义的备选空间时，它保持克制。

## Alternatives considered

**为每个设计或改进任务自动触发创意模式。** 不采用，因为普通实现与评审通常需要忠实遵循契约，而不是未经请求地发散；宽泛触发还会与排障和验证工作流竞争。

**把永久创意人格写入根 agent 指令。** 不采用，因为仓库级人格会影响每项任务，无法按请求选择或省略。

## Consequences

用户按名称选择工作流，并获得稳定的强度与样式控制。Agent 不会仅因任务提到架构、设计或改进就宣传或加载该工作流。仓库把工作流正文及其 technique 参考作为开发指引维护，而不是产品运行时契约。
