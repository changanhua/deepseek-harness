# Agent Note: 项目计划分别保留意图与执行事实

Status: implemented

[English](2026-09-27-project-planning-and-execution-boundaries.md) | 中文

## Problem

有价值的工作想法会在多次会话中逐渐形成，此时范围和验收条件往往尚未确定。要求填写完整任务表单会丢失这些想法；把每个建议当成可执行任务则会虚构承诺。后续讨论需要持续完善同一对象，同时保留原始来源和实际交给执行者的版本。

现有[同会话 Goal](../feature/2026-07-19-persisted-same-session-goal-domain.zh.md)拥有单个 Session 内的持续推进语义。[Delivery 与 Queue](2026-08-30-delivery-queue-bridge.zh.md)拥有受控执行和恢复，[项目记忆](../feature/2026-09-08-project-memory-v1.zh.md)拥有经过来源校验的经验和人工接纳。这些领域均不拥有跨会话、持续演化的项目意图池，各自的既有决策继续有效。

## Decision

可选 Planning 组合拥有项目内的卡片、不可变修订、待采纳草稿代次、人工泳道与排序、估计、依赖、复盘以及执行的持久关联。Agent 根据普通对话意图加载随包提供的 Skill。可明确定位的用户修改直接使用当前版本提交；推断得到的重要修改保留为草稿，采纳时指定精确代次。来源内容提供依据，不授予操作权限。

非结构化收录会把原文作为未经验证的来源保存在待处理 Proposal 上。范围、验收、估计和边界等可选细节保持为空，直到 Planning 对它们进行演绎。工作台不会由这次收录直接创建 active item；采纳一个精确的 Proposal 代次才执行该转换。

Planning Definition 从分离的 Board 快照派生演变视图。来源、Proposal 代次、已采纳修订、复盘、依赖和 Delivery 交接形成稳定节点与边。待处理和已否决方案保留在已接受主干之外。该投影不调用模型，也不虚构 Board 未保留的历史泳道或依赖值。

Planning MCP 网关使用其 Host 已拥有的 Provider。操作人授权已注册项目，可选用精确路径限制访问范围，并通过环境变量或私有凭据文件提供的 bearer token 认证请求。调用选择获准项目，不必更改服务配置；连接器可从可信当前项目上下文补充省略的选择，选择不明确时拒绝操作。现有连接器保留其他能力，新增项目发现、分页搜索、精确读取和待处理 Proposal 收录。Host 固定 actor 权限，并将外部文字标为未验证的手动来源。调用者不能伪造可信 Session 来源或来源身份，不能采纳 Proposal、修改项目记忆或派发 Delivery 工作。可选 delta 的来源及证据保留为未验证外部引用。

一个有容量上限的 Board 记录将修改、审计事件和重试回执一起提交。每个存储命名空间由单个 Host 拥有写入权。Board 与对象版本检查拒绝陈旧修改；重放相同请求返回已提交结果。复盘引用条目的不可变修订。从复盘创建后续项时，新条目与复盘关联原子提交。

Agent 直接创建或修订时，如果模型漏传发起请求的用户消息，Provider 会把经过校验的该消息加入修订来源。采集发生在回执重放查询之后，不改变提交的命令，因此相同请求重试时身份保持一致。来源列表已满时拒绝写入，不丢弃发起消息。

执行交接在调用 Delivery 之前固定精确计划修订、来源快照、映射器身份和请求摘要。结果不确定时，桥接层复用持久幂等键，并在创建成功后回挂返回的 Case。桥接层不创建 Queue 生命周期、需求批准、执行派发或人工验收。产品范围进入 Delivery 合同；Packet 路径权限和可执行验证仍由 Delivery 拥有。后续计划编辑不改写已固定的交接。

Planning 通过关联 Case 读取 Delivery 的当前投影和不可变证据，不持久化执行状态副本。执行、验证、人工验收和复盘保持为不同事实。经验沿用项目记忆的候选和人工接纳流程。知识捕获保留带版本的来源文本，不表示已经生成或发布知识内容。

正式工作状态由当前不可变修订投影，包括可选且具有稳定 ID 的状态条目。可选 Focus 记录用于选择 Plan 的一部分，不引入任务层级，也不推导父对象完成。可扩展资源引用只保留外部身份，所属系统继续拥有状态和权限。Session 绑定独立于 UI 选择，保留原始作用对象和基础修订。已绑定 Session 提出变更，由人采用精确代次。同一个 Board 事务应用 delta 操作、记录来源并推进正式修订，基础版本过期时拒绝且不留下部分改动。Thinking Desktop 可以使用这些引用及提案边界，无需在 Planning 中增加探索存储。

SBC 探索存储是显式启用的 Remote 能力，使用独立记录和案例版本。它将既有 Planning 修订及可选 Focus 保留为冻结投影，在读取时比较当前身份，始终不调用 Planning 修改。按案例分文件、以逆向移动记录撤销历史，使每次写入有界；初始化失败后可显式重试。生成 Remote 的浏览器测试在组合的 personal-planning 层验证拖动、选择、撤销、重载和可见漂移。可选本地验收输入将个人 Board 复制到隔离存储，不修改原始记录；这不构成正在运行的个人实例部署证据。

## Alternatives considered

- **用一个 Session Goal 表示项目待办池。** 不采用，因为 Goal 的持续执行权限、预算和 Session 生命周期无法表达跨会话独立安排的多个意图。
- **推断后立即执行。** 不采用，因为识别一个想法既不表示用户批准了推断计划，也不表示允许执行。草稿保留进展而不虚构承诺。
- **新增执行或记忆状态机。** 不采用，因为 Delivery、Queue 和项目记忆已经拥有相应状态转换和恢复规则。持久身份与读取时投影可以连接它们，而不引入竞争的数据权威。
- **依靠内存交接或跨存储事务。** 不采用，因为进程可能在 Delivery 创建成功后、Planning 收到结果前停止。准备记录与确定性重试覆盖此窗口，无需假设跨存储原子写入。
- **依赖模型附上发起消息来源。** 不采用，因为模型可能保留旧来源，却漏掉授权新修订的消息；Provider 已校验该消息，可以在不改变请求摘要的情况下采集它。
- **为 MCP 新建收录存储或 Planning Provider。** 不采用，因为 Proposal 代次已经能够表达未完成的理解，而第二个 Provider 会引入竞争的项目权威和存储所有权。
- **将探索坐标保存在 canonical Board 中，或为每次撤销保存完整布局。** 不采用，因为空间探索不代表 Planning 决策，完整布局会成倍增加持久化开销。独立案例记录和逆向坐标保留两者的区别。

## Consequences

用户可以通过对话完善计划，并在工作台查看同一批对象。带来源的修订使后续执行或经验能够追溯到形成它的讨论。缺少依据的估计保留为未知，建议优先级不覆盖人工顺序，归档不证明完成。

收录想法的成本低且可逆，而采纳仍需明确操作。相同快照在刷新和不同 Session 中生成相同演变图。MCP 客户端获得一条狭窄的贡献路径；部署通过 Host 环境或私有文件提供端点凭据。列表分页固定 Board 版本，对象续读固定不可变修订或 Proposal 代次。写入结果不确定时保留原请求身份，不会自动重新提交。

有容量上限、单写入者的 Board 不提供多主机并发修改。语义意图识别属于模型和 Skill；Host 执行项目访问、真实来源身份、严格命令和版本检查，不宣称能证明自然语言意图。因此，真实模型行为需要在 Provider 与 schema 测试之外独立验收。

真实 Loader 测试覆盖草稿与交接恢复；执行生命周期测试使用真实 Git、Queue、证据和验证，仅替换外部 Codex 传输。该测试不证明真实外部执行或个人 Profile 已安装，这两项需要各自的运行观察。
