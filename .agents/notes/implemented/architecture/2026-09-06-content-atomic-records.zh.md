# Agent Note: 原子内容记录与独立草稿

Status: implemented

[English](2026-09-06-content-atomic-records.md) | 中文

## 问题

有用文本需要在来源会话消失后仍可访问。编辑不能悄悄替换原文，响应丢失也不能让重试产生重复版本。若内容、修订和回执分开写入，就可能确认一个只提交了一部分的状态。

## 决策

个人[内容定义](../../../../packages/content/content/README.zh.md) 将不可变版本与可编辑草稿分开。[领域提供方](../../../../packages/content/content-domain/README.zh.md) 通过 Storage Domain 替换一个完整条目聚合记录，其中包含修改回执。短暂的库级命令链比较最新修订，并在写入前核算全部保留数据。它不调度 agent（智能体）工作，也不持久化另一套执行生命周期。

来源捕获接收可信宿主解析器，不从客户端载荷接受已核实文本。提供方在准入时检查权限，并在来源准备完成后于修改链中再次检查。读取同样要求授权。Schema 保留原样文本，提供方重新打开时核验正文摘要。服务返回独立副本，不暴露可变的 Domain 记录。

创建与版本操作永久保留请求身份。有界的近期回执窗口支持其他修改；超出窗口的请求仍携带预期修订。元数据比较条目修订，草稿文本比较自身修订与基础版本，从而避免无关元数据变化制造文本冲突。

内容领域要求[存储保证](2026-09-06-storage-backend-guarantees.zh.md)，但不拥有数据库连接。其不可用状态独立于现有 Session 和存储消费方。后端所有权及关闭责任仍由存储插件承担；连接可疑时，恢复必须同时替换内容提供方及其专用后端。

## 考虑过的替代方案

**把内容保存在 Session 历史中。** 拒绝，因为独立保留、编辑和来源可用性需要不同的所有权。Session 保持来源引用职责，不承担内容库。

**将版本、草稿和回执分表写入。** 拒绝，因为当前公开 Domain API 不提供跨记录事务。一个聚合记录无需额外事务平台即可提供所需原子提交。

**文本更新采用最后写入获胜。** 拒绝，因为并发编辑可能擦除人类输入。明确的修订冲突同时保留已存文本和调用方尚未保存的文本。

**把每次按键都记录成不可变版本。** 拒绝，因为自动保存和主动形成版本的保留成本不同。草稿承接自动保存，直到消费方提交一个版本。

## 后果

定义与提供方使用个人包命名空间，可独立演化，无需替换原生 agent 工具。两个包均不提供 agent 工具、MCP 端点、人类 Remote 或 UI。来源桥接和浏览器工作流验收仍属独立交付内容。

全领域加载和聚合替换限制了初始内容库规模。配置的字节上限拒绝追加写入，不截断历史。数据超过新调低的上限时仍可读取与导出。物理连接随专用后端生命周期释放；内容提供方关闭自身 Domain 句柄，并停止使用可疑缓存提供数据。
