# Agent Note: Provider 所属的 Skill 目录资源

Status: implemented

[English](2026-09-27-skill-bundle-resources.md) | 中文

## 问题

限定能力范围的 Agent 可以加载 Skill，却没有通用文件系统工具，因而读不到其中引用的应用模型和流程。把返回的目录路径直接当作读取权限，会绕过选中该 Skill 的 provider、作用域优先级和调用策略。

## 决策

既有 Skill 服务把附件读取委托给选中的 provider。模型侧 `skill` 工具声明调用用途；候选策略、当前定义和精确注册在加载过程中保持绑定。provider 释放、调用取消或作用域胜出项变化都会阻止返回旧内容。资源基址元数据不授予文件访问权。

本地 provider 接受目录型 bundle 内的规范相对路径，检查文件系统包含关系，返回完整且有大小上限的 UTF-8 文本。平铺 Skill 文件没有附件命名空间。工具将附件与主文分开呈现，不会因为读到了代码就自动运行它。

本决策扩展 [Skill 调用策略](../feature/2026-07-28-skill-invocation-policy.zh.md)，并支持[应用流程](2026-09-27-browser-application-bindings.zh.md)。两项决策继续有效，均未被取代。

## 考虑过的替代方案

**给所有 Skill 消费者开放文件系统工具。** 这比读取所选目录包需要的操作范围更广，也不能覆盖非文件系统 provider。

**将所有附件内嵌到主文。** 这会失去按需加载，并重复为当前任务用不到的代码和应用模型消耗上下文。

**由消费者根据 resourceBase 读取附件。** 元数据会变成权限依据，使主文与资源的 provider 覆盖和生命周期检查分离。

## 后果

provider 按需支持附件，不支持的读取明确失败。完整文本和渲染结果有字节上限，不静默截断。必需证据覆盖胜出作用域、模型调用策略变化、精确注册替换、释放、路径包含关系、文本拒绝，以及组合后的 Agent 加载所选资源。浏览器流程继续使用原工具管线和任务权限。
