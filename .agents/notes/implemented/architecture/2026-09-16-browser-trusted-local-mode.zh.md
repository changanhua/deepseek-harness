# Agent Note: 浏览器本地可信模式

Status: implemented

[English](2026-09-16-browser-trusted-local-mode.md) | 中文

## 问题

对于任意浏览器扩展，所有者交互批准是安全默认值；但个人 Web 组合已经指定一个由所有者选择的 Chrome 解压扩展，并通过 loopback Host 为它提供服务。重新安装该扩展会生成新的安装身份，而旧授权仍持久保留，因此重复设置可能耗尽人工授权上限，并要求同一所有者再次批准组合已经选定的身份。

## 决策

`BrowserExtension.Config.trustedExtensionIds` 声明本地 Host 无需交互配对即可接受的扩展 ID。通用包默认列表为空。个人 Web 组合声明 `cimpmgjgfahhppmekdecgnboipoaajcf`；请求 `Origin`、请求正文和配置 ID 必须精确匹配，Host 才进入此路径。

可信 `/connect` 原子签发所申请 scopes 与 origins、轮换后的持久传输令牌，并直接返回已连接授权。Chrome 扩展在持久化凭据并启动 WebSocket 前，校验返回的安装、扩展、scopes、origins、代次和令牌。Chrome 站点权限仍是由浏览器独立拥有的边界。

每个已配置可信扩展拥有一个持久安装槽位，且不占用人工批准授权上限。新安装会推进授权代次，替换该扩展 ID 的全部旧安装，断开旧的在线 peer，并使其令牌失效。Host 启动时迁移同 ID 的旧授权，仅保留最高代次并将其标记为可信。配置移除该 ID 后，这份可信记录会在下次 Host 激活时按 fail-closed 删除。人工批准的扩展继续使用有界 pending、批准、容量和撤销流程。

安装令牌仍是 WebSocket 认证与重启恢复的必要条件。配置可信只移除重复的所有者决策；它不移除传输身份、请求权限校验、动作审批、日志恢复或页面证据规则。

## 考虑过的替代方案

**提高人工授权上限或淘汰旧授权。** 更高上限只会推迟同一故障，而隐式淘汰会让无关的已批准安装失去权限。两者都没有移除个人组合已经选定扩展后的冗余批准决策。

**信任 loopback 上的所有 Chrome 扩展。** Loopback 识别机器，而不识别预期浏览器主体。该模式保持显式启用并固定精确扩展 ID，普通扩展和第三方扩展仍走人工批准路径。

**移除可信扩展的安装令牌。** 扩展 ID 与 HTTP `Origin` 选择可信路径，却不能提供可跨重启保留的连接凭据。保留轮换令牌可以继续执行 WebSocket 认证、代次围栏、安装替换和泄露凭据失效。

## 结果与影响

个人扩展连接时不打开 DSH 批准页面，重新安装也不会累积授权或触发人工授权容量。既有人工部署保持原行为，因为通用包默认不信任任何扩展。

该模式有意把本地操作系统账户及其配置的 loopback 组合视为所有者边界。本机原生进程可以伪造 HTTP `Origin`，因此配置的扩展 ID 无法对抗已经以该用户身份运行的恶意代码。移除配置 ID 并重启 Host 是持久撤销路径。共享同一扩展 ID 的不同 Chrome profile 也共享一个可信槽位并相互替换；个人组合接受这一单 profile 取舍。
