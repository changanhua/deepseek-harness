# Agent Note: 应用知识与新鲜浏览器绑定

Status: implemented

[English](2026-09-27-browser-application-bindings.md) | 中文

## 问题

每次从原始浏览器控件中选动作，都会重复解释页面和业务字段。更快的选择器仍要为已知含义付出请求成本；把生成的控件引用与应用知识一起长期保存，又会把过期页面身份带入后续任务。

## 决策

稳定应用知识与可选流程模板放在仓库 Skill。[GitHub Issues Skill](../../../skills/github-issues/SKILL.md) 描述页面路径、控件含义及查重、表单回读要求。知识同时包含隔离页面和已观察的 GitHub 列表控件；每次真实使用仍需新鲜确认。

其[可调用流程](../../../skills/github-issues/references/execution.md)使用调用方原有浏览器工具，将歧义和不确定阶段交回 Agent。DSH 经所选 Skill provider 加载附件，通过 `run_code` 执行可选的确定步骤，保留 BrowserTask 与发起 Agent。Codex 在当前代码执行环境中调用原有 MCP 工具，保留该连接的请求归属。流程不保存第二份任务账本、不靠重放输入恢复，也不从提交回执推断创建成功。[Skill 附件决策](2026-09-27-skill-bundle-resources.zh.md)负责资源读取边界。

既有 `browser_snapshot` 消费者接收有界的语义控件描述，从本次读取的原始引用派生绑定。只有完整、未过滤的观察中恰好一个合格匹配项才返回 `bound`；部分、缺失、歧义和页面不匹配均明确返回。每个结果标明读取来源。绑定器不保存引用、不派发动作、不判断业务完成，也不另建任务账本。预算、页面身份、授权和未知写入仍由 BrowserTask 与 Provider 检查负责。

本决策补充[执行授权决策](2026-09-08-browser-execution-authority.zh.md)与[显式表单回读](../bug-fix/2026-09-27-browser-form-readback.zh.md)。[平台提案](../../proposed/architecture/2026-09-26-browser-capability-platform.zh.md)保留更广的任务范围工作，以上记录均未被替代。

## 考虑过的替代方案

**新增流程服务或证据库。** 既有任务的 attempts、receipts 和 checks 已经负责执行。增加第二个拥有者会重复恢复和授权规则。

**把站点选择器写入扩展。** 这会让执行器负责业务知识，并让页面变化牵动扩展发布。应用描述放在该边界上层。

**把每个已知步骤交给更快的模型。** 选择器仍适合真实歧义；当前证据已经确定唯一动作时，这次推理等待可以省去。表示方式和流程编排须分别测量，单独增加语义名称不保证减少模型调用。

## 后果

快照标注按需启用且有上限，引用由既有工具执行，不增加权限或自动提交。导航后操作引用必须重建；此前的限定范围搜索事实按各自时效判断，不一律作废。通用任务检查器不会自动证明查重覆盖或外部服务恰好创建一次。源码测试覆盖部分观察与绑定歧义，真实 Loader/Chromium 测试将返回引用交给既有任务执行并观察回读。独立 MCP reader 没有绑定参数，调用方可将同一知识应用于其新鲜观察。
