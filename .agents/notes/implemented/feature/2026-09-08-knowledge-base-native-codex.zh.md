# Agent Note: 使用原生 Codex 执行的知识库

Status: implemented

[English](2026-09-08-knowledge-base-native-codex.md) | 中文

## 问题

生成式知识库需要可编辑内容、可追溯来源、可重算检查和可恢复执行。模型响应可能先于进程清理或文件提交而存在。把所有中断当作重试会重复付费调用；把 Markdown 当作执行历史，会丢失“已有返回结果”与“结果未知”的区别。

## 决策

个人下游的[知识包族](../../../../packages/knowledge/README.zh.md)分别维护业务记录、类型化 Queue 执行和用户操作。知识 Domain 拥有已确认规格、不可变来源版本、阶段输入、已捕获响应及发布记录。Queue 拥有 Work/Attempt 状态。来源快照、版本导出和不可变产物保留执行证据。可选思源投影拥有可编辑文档映射、观测基线和创建意图。Profile bundle 在现有存储与子进程能力之上组合这些服务。

阶段在准入前固定提示词和输入身份。Queue 桥接先绑定 Work，再调用已有的原生 Codex App Server 适配器。它在清理前保存已返回响应，清理完成后才接收内容。显式恢复操作核验已捕获响应或待发布候选，不为未知远程调用伪造结果。适配器未暴露原生继承的实际模型身份或用量时，相应信息保留为 unknown。

生成通过声明的 Queue 资源串行执行。持久停止记录在配额失败后阻止新调用，并跨重启保留。格式修正建立绑定已拒绝响应的新输入，有限 build 上限防止格式修正和审查回环无限执行。未知结果需要操作者明确处理。

正式发布要求当前必需覆盖与审查通过。每个版本的 manifest 覆盖内容和元数据文件。来源导出保留追溯元数据，条目保存其使用的引用节选。部分草稿必须显式导出，不能成为当前正式版本。Domain 是当前发布版本的权威来源，仓库打开时会在发布中断后重建文件投影。回退核验指定发布版本并切换选择，不替换可编辑工作区。

通过既有原生 MCP client 配置思源后，同步会从正式发布版本创建首次可编辑条目文档。后续生成内容保存为单独命名的候选，不会覆盖既有条目文档。人员在接纳前检查标题/正文快照；接纳记录已接受内容并使其审查失效。来源和适用条件段保持受来源控制，拒绝接纳对它们的变更。创建意图在派发前持久保存。已派发创建后缺失文档会作为未知继续点保留给操作者处理；此版本没有操作者处理 action。

## 考虑过的替代方案

**独立的知识 CLI 与文件调度器。** 这会重复受支持的应用启动、Queue 尝试、存储归属和进程清理，因此功能使用 DSH 工具与命令。

**自动重试所有中断调用。** 原生适配器暴露一轮临时 turn，没有持久远程结果查询。未知调用不能安全地视为已知失败；本地响应保存与显式操作者处理保留了这一区别。

**回退时改写工作文件。** 这会丢失发布后的用户编辑。不可变发布版本的选择将历史阅读与当前编辑分开。

**将思源作为未跟踪的渲染目标。** 这会使人工编辑脱离项目证据，并允许后续生成写入覆盖它们。投影记录稳定文档身份，并通过同一项目记录接纳已检查的编辑。

## 影响

知识地图是生成器对每个主题的统一交付契约。由持久规划和条目确定性派生的同一结构，驱动当前地图命令、版本化 Markdown/JSON 导出及思源地图。复用一个表示避免仅为样例制作导航，也避免增加另一份可变地图权威。已发布地图读取冻结的发布规格；思源地图变化或缺失时，同步不能报告完成。

上述分工保留可编辑内容与执行证据，不增加第二份可写任务账本。备份必须同时包含来源快照、导出、对应 Domain/Queue 数据和思源映射记录。文件发布和思源投影都不承诺跨存储事务或断电耐久。引用位置检查和模型审查不能证明领域完备，也不能替代读者验证。首个内容配置侧重 AI 辅助游戏开发，较小的摄影样例复用同一契约。
