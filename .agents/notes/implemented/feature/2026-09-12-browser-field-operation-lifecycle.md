# Agent Note: Browser field operation lifecycle

Status: implemented

English | [中文](2026-09-12-browser-field-operation-lifecycle.zh.md)

## Problem

Browser tools exposed individual reads and writes but lacked a durable authority for the complete lifecycle of a field task. A model could not query an uncertain request without replaying it, a planned group of actions paid one model round trip per step, a page result panel had no shared ownership or cleanup contract across the Browser provider and a dynamic Cordis Plugin, and process-local task state could not recover after a Host restart. Tool presence alone therefore did not guarantee that recovery, page targeting, task acceptance, and retraction composed into one usable flow.

## Decision

The Browser service owns explicit request identity, executor capability declaration, exact page identity, action transport, and page-workspace actions. A request has a caller-minted id and caller-scoped retained status that is read without replay and without exposing its authority fingerprint. Before a write crosses the extension boundary, BrowserTask records a `dispatch-intent` with an action-free recovery locator and flushes the owning Session. A Host that loses its request memory may use that locator only to query the extension journal; a missing, mismatched, offline, or expired record remains `unknown` and never causes the action to execute again. An online executor declares protocol version, implemented action kinds, in-process request recovery, and optional restart journal lookup during its authenticated handshake.

A page workspace starts with `page_map`. The Host converts each bounded exact-document region into an opaque, short-lived `regionRef`; model tools, Session evidence, and dynamic packages do not receive its CSS selector. `region_render` accepts a bounded high-level presentation of titles, summaries, items, facts, links, and footer text. The provider resolves the reference, compiles that presentation into the page runtime's plain-data blocks, and permits replace mode only for the referenced disposable, non-protected region. Links accept only HTTP(S), and the extension renders content as text nodes. A new map, authorization epoch, document, URL, Session, installation, or expiry invalidates the old reference.

`@changanhua/dsh-browser-task` owns the Session-persistent field-task projection and the Browser service's common operation lifecycle. Ordinary tools, prepared commits, direct Provider callers, and dynamic Cordis calls therefore share one exact Agent and Session owner, action budget, evidence history, attempt lifecycle, recovery policy, and resource responsibility. Caller-local validation completes before a caller acquires ownership or reserves task budget. Prepared commits and direct Provider execution use an exact request-id lifecycle: concurrent repeats join the original work or its retained terminal result, while the same request id paired with a different action is a conflict. The provider records an action-free `dispatch-intent` and recovery locator before it sends a write; a sent or unknown request is subsequently status-queried by that exact identity and is never re-executed.

Deterministic failures retain a semantic fingerprint that excludes request and mount ids. The task blocks an unchanged action after its first failure and restores execution only for a materially different target or later page-map evidence that proves the failed precondition has changed. A sent unknown write is reconcile-only, and an internal fold invariant pauses the task as an internal blocker rather than becoming a browser error the model can retry. Prepared records retain their in-flight or terminal disposition across expiry, so expiry cannot produce a second send after a racing commit. Direct-operation retention likewise preserves in-flight and unknown-sent work rather than evicting it for capacity.

The projection also separates immutable evidence and target binding, action receipts, page-resource leases, capability snapshots, canonical Subagent/Job/Cordis identities, and acceptance checks. Delegation output enters only as a bounded digest and never counts as acceptance by itself. A region presentation clause requires the exact observed render receipt plus a later fresh page observation of its text, then completion waits for the region's receipt-backed cleanup disposition. Every other clause likewise needs checker-backed current evidence; no blocker or unresolved write may remain, and budgets stay bounded. V1 rejects retained resources; explicit Session/user ownership transfer is deferred. The tool-browser loop is a stateless continuation and checker facade over that projection; it never becomes a second task authority.

The dynamic Cordis runner captures the exact live Agent at definition time and executes every Browser call and cleanup inside that initiator scope. Plugin versions cannot reset task budgets or recovery history. Local mount and render validation happens before the runner records resource ownership. Agent-scope teardown runs while that Agent is still live, so stop, update, startup failure, undefine, and owner disposal use the same resource settlement path. A stronger `forgetCollected` finalizer remains a distinct cleanup intent when an earlier ordinary release has already settled; it cannot be silently satisfied by that weaker cleanup. If the owning BrowserTask has already become terminal, only a cleanup that the runner previously registered for that exact owner transfers to the runner cleanup ledger. The runner then reconciles its original request identity without reopening the terminal task; arbitrary Plugin work cannot take this detached path. The facade exposes `harness.browser.pageMap`, `render`, and `restore`; it does not create a second page protocol or accept a caller-supplied Session identity.

## Alternatives considered

**Add only model-facing tools.** This would make schemas visible while leaving dynamic Cordis Plugins unable to own and retract the same region resources, which is the runtime path used for persistent in-page adaptations.

**Expose unique selectors and low-level blocks to the model.** Uniqueness prevents ambiguous DOM writes but still makes a probabilistic caller calculate addresses and implement a rendering protocol. Opaque references and a high-level presentation retain the same page-runtime capability while removing those two error classes from model-visible input.

**Treat stop or timeout as successful cleanup.** A request can cross the extension boundary before its receipt is lost. Pending cleanup therefore survives an unknown outcome and blocks unsafe rebinding until a later clear is observed.

**Persist page-region state as durable product data.** A region belongs to one live document and extension runtime. Durable storage would outlive the object it identifies and still could not restore a replaced document after browser or Host loss, so this decision keeps the resource process-local and makes that limitation explicit.

**Let each tool or dynamic package implement recovery.** That would make direct Provider calls, prepared commits, and generated tools disagree about budgets, dispatch durability, unknown effects, and cleanup. The common Browser lifecycle keeps policy in BrowserTask while leaving callers free to choose or create a different safe method.

## Consequences

The field agent has one durable recovery, page-workspace, and acceptance lifecycle instead of unrelated helper calls. It can choose a different mapped region, presentation strategy, or temporary Plugin implementation after new evidence, but it cannot invent authority, execution facts, or success evidence. Fewer model round trips do not bypass local validation, preparation, authorization, stale-page checks, upload provenance, budgets, or dispatch persistence. Dynamic Plugin teardown returns cleanup-pending identities when restoration is unresolved, while a terminal task does not strand an already-registered cleanup or grant detached execution authority to other Plugin actions.

Page maps, opaque references, and region state remain bounded in memory. A Host restart can recover a retained extension receipt but cannot revive an old region reference; it must map the live page again. Journal expiry, extension storage loss, or an unavailable executor leaves the write unknown. A document replacement clears the page-side mount, while a simultaneous Host and extension loss can leave no owner able to prove restoration and requires owner-visible reconciliation rather than a retry claim.
