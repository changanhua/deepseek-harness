# Agent Note：Work Observatory 证据计时

状态：已实现

[English](2026-09-03-work-observatory-evidence-accounting.md) | 中文

## 问题

Web 产品需要一种面向用户的方式，用来检查人和一个或多个 Agent Session 何时处于活跃状态，同时不能把薄弱的本地信号包装成生产力结论。浏览器时钟不具权威性，多个标签页与 Session 可能重叠，Session 执行拥有持久 step 边界而不是 CPU 计时，存储子系统也已拥有后端可移植性和生命周期。可信视图必须同时在数据模型与 UI 中说明这些边界。

## 决策

Work Observatory 是由 Host 服务支持的专用 Web 工作区。浏览器发送状态与单调递增的文档序号，但不发送时间戳；Host 为接受的观测盖时间戳。人类活跃表示页面可见、获得焦点且近期发生过交互。Agent 活跃表示 Session step 打开期间的墙钟时间。页面可见、人类活跃和 Agent step 区间分别归一化；重叠与 Agent 单独时长从这些归一化集合派生。多个标签页和 Session 不会让同一个墙钟时刻在首要汇总中重复计数。

Host 通过 `ctx.storageDomain` 持久保存版本化、逐记录布局的 `work_observatory` 域。状态转换、最新浏览器状态与 Session step 分别使用独立表。未变化的心跳只延长最新 Host 证据；记录键使用路径安全哈希；保留期与查询大小有明确边界；关闭时会等待排队写入完成后再关闭存储域。Client 只拥有一个文档级追踪器，串行执行 Remote 写入，文档隐藏时重置人类活跃状态，并随插件 fiber 释放监听器与定时器。

工作区允许用户选择本地日期；当前 Session 存在规范项目路径时会沿用该路径；它先展示来源区间，再展示汇总，并可打开有贡献的 Session。说明文案会明确拒绝生产力和节省时间的解释。

## 考虑过的替代方案

**复用以前直接连接 SQLite 的实现。** 该分支早于当前存储域约定和包组合。它的产品语义值得复用；复制其持久化路径则会绕过当前所有权、后端可移植性与关闭规则。

**把视图放进设置。** 这个视图是带日期导航和 Session 下钻的日常工作界面，不是配置项。专用侧栏工作区能保持可发现性，同时不把证据与偏好混在一起。

**报告生产力或节省时间。** 页面可见状态与开放 step 墙钟时间无法证明产出质量、因果投入或反事实节省。产品只报告证据区间。

**在首个包中耦合 Queue、Delivery 与 Skill 数据。** 这些领域拥有独立生命周期与语义。未来可由可选桥接包加入明确事实；基础计时不依赖它们也能保持有用并可测试。

## 后果

首个纵向切面让本地部署拥有持久、可检查的人类／Agent 墙钟证据，并且只使用一个 Host 权威来源和一套区间算法。它不会观测 Web 文档之外的活动、跨缺失心跳外推、聚合多个 Host，也不会把时长归因到某个 Skill。Agent 时间可以包含开放 step 内的 Provider、Tool、子 Agent 与等待人的区间。这些负面保证仍是未来 Queue、Delivery、Skill 或遥测桥接必须遵守的约定。
