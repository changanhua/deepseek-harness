# Agent Note: 项目资源与手动服务所有权

Status: implemented

[English](2026-09-09-project-resources.md) | 中文

## Problem

高频使用的资料、文件和本地服务命令需要在会话之外有稳定归属。反复寻找路径和重建启动命令会增加简单项目工作的成本。

## Decision

[Workspace Controller](../../../../packages/api/workspace-controller/README.zh.md#project-resources) 管理项目内配置文件，以及通过已有本地 subprocess Provider 创建的进程句柄。[Workspace UI](../../../../packages/client/ui-workspace/README.zh.md) 在现有项目页增加简小的资源区。资料仍是普通 Markdown，已有文件保留原位置。不引入自动知识提炼、外部同步、模型工具、服务依赖图或重启调度器。

文件变更按项目串行，在替换配置前取得短期排他写入锁。读取拒绝损坏配置，不自动修复。进程归启动它的 Host 所有，独立于当前会话。同一 Host 中重复启动复用现有活动句柄。停止与释放等待所拥有的进程树退出；停止不依赖项目目录仍然可用。

## Alternatives considered

**新增知识数据库和通用资源注册中心。** 普通文件与小配置已能满足首批使用方，无需新的索引或同步系统。

**把会话 Jobs 当作永久服务。** 它们的进程内所有者生命周期无法表达手动控制的项目服务的独立存续范围。

**重启后自动恢复服务。** 手动启动保留首版明确的执行边界，无需加入依赖、就绪和重启策略。

## Consequences

用户可以跨会话和 Host 重启复用资源，无需复制原文件。服务状态和最近日志是本 Host 进程的观察结果，不是持久健康结论。移除登记后文件保留。项目相对路径与规范化链接检查限定文件操作范围；不会接管外部进程或按端口号杀进程。

文本预览有大小上限；二进制查看、自动发现、知识同步、持久日志和崩溃恢复不属于本实现。写入方崩溃可能留下锁，需要明确检查后才能移除。浏览器验收覆盖文件、真实 HTTP 监听、导航、停止和 Host 重开；针对性测试覆盖写冲突、无效路径与清理。
