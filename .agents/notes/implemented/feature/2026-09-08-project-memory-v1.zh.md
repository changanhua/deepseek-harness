# Agent Note: 有来源的项目记忆记录

Status: implemented

[English](2026-09-08-project-memory-v1.md) | 中文

## 问题

Session 检索保留说过的内容，但可复用项目命题还需要明确接纳、来源、版本和防止陈旧复用的条件。将 agent（智能体）总结视为当前事实会丢失这些区别，让过时指令跨会话累积。

## 决策

记忆 Definition 分开保存候选、人工决策与派生的来源可用性。本地 provider 将记录绑定到既有 Workspace 身份，自行捕获来源指纹，并通过一次 Storage Domain 更新持久化记录及其幂等回执。不可变内容版本不保存可变的接纳期限；每次人工接纳拥有自己的复核日期。

召回排除待处理、已撤回、逾期、冲突、来源改变与来源不可读的命题。来源不可读并不证明命题错误。文件来源使用 Agent 的文件系统能力；Session 来源使用实际落盘事件，不使用只存在于内存或恢复时合成的事实。记忆文本不授予工具权限，也不替换当前用户指令。

## 后果

本地域只有一个 Host 写入者，由独占所有者文件保护。已有锁绝不会被自动删除。正常卸载在释放所有权前等待写入完成；崩溃恢复要求先核验之前的进程，再移除精确的锁。这以无人值守恢复能力为代价，保持首版有界，不引入跨进程 CAS 或自动所有权转移。

## 考虑过的替代方案

只有 Session 历史无法表达已接纳知识或当前来源可用性。外部记忆服务器仍可通过[通用 MCP 示例](2026-07-31-third-party-memory-mcp-examples.zh.md) 独立使用，但其厂商契约不拥有 DSH 的 Workspace 授权与原生人工命令决策。两种能力保留各自的状态所有权。

向量数据库或自动归并不能解决来源有效性或权限边界。词法排序和显式主题冲突提供可测量基线，无需引入另一个持久事实存储。

## 验证

包测试使用真实 Storage Domain，覆盖 JSON 与 SQLite 重开、并发版本检查、写入失败和幂等恢复。来源测试使用真实文件读取、Windows junction 范围检查和 JSONL 持久事件。独立进程验证所有者排他性；服务测试覆盖候选隔离、精确人工命令绑定、新会话读取、来源变化和冲突命题。这些检查不证明发布 Profile、真实模型使用或浏览器验收；宣称完整用户流程完成前必须另行取得这些观察。
