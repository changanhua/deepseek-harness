# Agent Note: Eval 场景扩展与浏览器试点

Status: proposed

[English](2026-09-10-eval-scenarios-and-browser-pilot.md) | 中文

## 问题

维护者需要比较 agent（智能体）能否完成真实任务、需要多少协助，以及实际消耗。一个浏览器任务可能需要识别页面、生成插件、点击入口、修改要求，以及停止插件并保留结果。最后一句回复正确，或插件启动响应成功，都不足以证明这些结果。

[已实现的 Eval 决策](../../implemented/architecture/2026-08-31-deterministic-eval-contract-and-snapshot-adapter.zh.md) 提供了有用的确定性基础。[用例 schema](../../../../packages/eval/eval/src/schema.ts) 要求一段提示词和每条路线一份回放 fixture（测试前置数据）；[runner](../../../../packages/eval/eval/src/runner.ts) 在调用执行器前就选择该 fixture；[运行 schema](../../../../packages/eval/eval/src/run.ts) 要求回放来源信息。这些限制使新的多轮真实执行场景无法直接表达。只添加浏览器断言，仍未解决执行、编写和证据归属。

本提案扩展这一 MVP。场景执行、浏览器适配器、独立自主浏览器验收均不在此声称已实现。它服务于 [Eval 执行与验收 Epic](https://github.com/changanhua/deepseek-harness/issues/49)，不改变或关闭该 Epic 更广的要求。

## 提案

保留现有 Eval 核心、确定性结果折叠、路线比较及 JSON/Markdown 报告。增加版本化场景契约，以浏览器适配器作为首个真实执行消费者。任务作者选择环境模板、填写用户消息和预期效果，并设置执行上限。将模板用于另一个页面时，不应需要修改 Eval 核心或重写生命周期脚本。

设计分为四种职责；它们不要求新建四套框架或四个包：

| 职责 | 归属 | 浏览器示例 |
| --- | --- | --- |
| 场景：任务、步骤、判据与预算 | Eval 校验公共结构；适配器校验自身载荷 | 创建入口、点击、改标签、停止 |
| 适配器：准备、执行与释放环境 | 与现有快照适配器并列的组合式适配器 | 隔离的 DSH profile 与浏览器、有时限的生命周期 |
| 观察器：采集外部结果事实 | 被测对象可写工作区以外的可信验证代码 | DOM 状态、实际侧栏记录、插件状态 |
| 判定器：判断观察事实是否满足判据 | 由可信计划选择的版本化确定性检查 | 条目与链接正确、去重、保留、清理 |

核心不负责浏览器选择器、DOM 解释、第二套 agent loop（智能体循环）、Queue 恢复或 Git worktree 管理。浏览器适配器起初拥有自己的观察器和判定器实现。只有另一个真实适配器需要相同行为时，才提取共享接口。运行时注册遵循 DSH 插件组合；纯 Eval 库不启动服务。

### 契约变更

以下名称是拟议字段，不是可调用 API。实现时必须同时更新 schema、执行器请求、结果校验、报告和快照适配器。

1. 引入 schema version 2，明确区分执行类型。`session-snapshot` 保留提示词、工作区和逐路线 fixture 规则；`scenario` 携带适配器标识、版本与经过校验的场景载荷。真实执行场景无需预先录制对话。未知类型、字段、适配器或判据版本在预检时失败。
2. 扩展现有 `EvalCaseExecutor` 请求，传入执行类型、解析后的路线、不可变计划身份及取消信号。一次执行器调用仍对应一个用例、路线和尝试；它可以执行多个步骤后返回。回放所有者支持更强的绑定前，保留顺序调度及稳定报告顺序。
3. 场景包含带稳定标识的有序步骤：用户消息、适配器动作和检查点。适配器动作与检查点采用已注册名称及类型化参数，不执行 Suite 中的任意代码。试点无需循环、表达式或通用工作流语言。有时限的条件等待由适配器动作内部负责。
4. 结果保留现有四种状态，增加逐步观察、判据结果、执行来源、协助分类及类型化指标和证据引用。DSH 执行仍须有真实 Session 事实。公共结果必须区分真实执行与回放，不能为真实运行编造回放文件。
5. 通过适配器明确支持的模式选择真实执行或回放。快照回放保留逐路线独立录制及既有绑定保证。其他适配器必须声明实际实现的模式；不支持的回放在启动前被拒绝。

迁移时保留既有快照场景及其预期判定。在实现改动中将仓库拥有的示例更新到 version 2；按照仓库预发布政策，可以对旧 version 1 输入返回明确的不支持版本错误。本提案不包含永久兼容层。新报告不得将旧回放结果重新解释为新的真实执行证据。

### 编写与执行流程

提供随仓库交付的浏览器场景模板及适配器编写指南。作者填写普通用户要求、目标环境、预期效果、路线选择与预算。自主用例不向模型提供正确选择器或插件实现。模板可以引用私有验证 fixture，但引用由可信 runner 解析，不进入模型输入或工具可读的被测文件。

同一份解析后的场景，通过受支持的 DSH 入口完成预检、单用例试跑、Suite 比较及报告导出。预检检查 schema、适配器能力、profile 与构建可用性、环境隔离、凭据权限和预算支持，不发起模型请求。单用例试跑直接展示失败步骤、预期效果、观察事实及证据链接，不要求先翻完整会话日志。CLI（命令行界面）和 UI 语法在其消费者实现时确定。

GitHub 可以标识待评测的已审查版本并展示检查结果；可信 DSH runner 拥有执行和持久证据。本地执行支持场景编写与浏览器试点。本增量不要求新建服务器部署、仪表盘、webhook 系统或通用制品库。组合相应执行集成时，既有 Queue、Session、工作区及预算所有者继续保持权威。

### 浏览器试点

将用户任务表达为生命周期场景。跨路线保持指令一致；各路线通过其获准的浏览器工具观察页面结构。

| 步骤 | 输入或动作 | 独立判据 |
| --- | --- | --- |
| 创建 | 要求在目标列表的每个条目旁添加入口，收集标题和链接 | 覆盖与条目关联正确；干扰区域不出现入口 |
| 点击 | 验证器点击选定的可见入口 | 侧栏包含该条目的实际标题和绝对链接 |
| 更新 | 要求入口改为“加入清单”、链接去重、标记已加入条目 | 已有记录保留；标签和已加入状态与记录一致；再次点击不新增重复项 |
| 停止 | 要求停止插件并保留收集结果 | 所有归属该插件的入口消失、事件不再接纳、收集记录保留 |
| 换页 | 在保留页面家族上，以相同要求运行全新用例 | 路线自行推导新结构，不接收前一个解答 |

验证器通过独立维护的 fixture 规范或已核对的来源数据推导预期条目集合，不采用插件自己选中的行作为答案。视觉位置与区域归属需要浏览器观察；挂载成功响应仅为补充证据。动态页面使用有时限的条件等待，不使用固定等待时间。受控 fixture 提供可重复状态；选定真实站点检验实际集成并记录页面和环境身份，不将站点当作确定性环境。

每个用例、路线和尝试获得隔离的 home、profile、会话及浏览器状态。适配器启动选定的 DSH profile、记录进程归属，并只关闭自身资源。可复用的不可变构建可以按摘要缓存；可变页面状态、收集记录、对话、凭据和插件实例不能跨比较单元传递。适配器在自身清场前观察产品清理结果，避免强制关闭浏览器让停止失败看起来成功。

取消信号传到被测执行。执行取消后，清场使用独立且有上限的清理额度；被测对象不配合时，可信监督者停止所属进程并记录未解决的产品状态。截止时间阻止无限等待。观察器或环境丢失会使结果不确定，不能悄悄变成模型失败或通过。

### 独立证据与失败归因

执行前冻结被测源码版本和构建、Suite 与场景摘要、验证代码及预期摘要、适配器版本、路线配置及获准环境输入。将实际观察到的 provider/model、提示词、工具与 skill（技能）身份、真实环境和请求身份一并记录。除非存在真实 Codex 适配器，否则外部 Codex 基线必须标为外部执行器；手写结果文件不等于原生 DSH 路线执行。

验证代码、预期与凭据放在被测对象可写、工具可读范围以外。agent 可以观察目标页面，但不能修改或读取判分实现。不可信 PR（Pull Request）不能替换可信判定器、扩大预算或选择凭据。DSH 评测修改过的 DSH 运行时代码时，控制方、被测方和验证方还须遵守仓库的[独立验证要求](../../../skills/dsh-change-verification/SKILL.md)。

每个检查点记录步骤标识、观察值、判据版本、结果、时间戳及按内容寻址的证据引用。采集足以解释判定的 DOM、截图、侧栏数据和 Session/工具事件，并在导出前遮蔽敏感值。证据包有明确的保留责任方；必需证据缺失或损坏，会使原本可消费的结果失效。可选截图不能替代必需的结构化事实。

保留 `invalid`、`infrastructure-uncertain`、`failed`、`passed` 及既有优先级。增加原因码和观察到的原因，不将全部失败合并为“模型能力不足”。判据或 schema 错误属于无效；观察器或网络丢失属于基础设施不确定；正常环境中观察到错误结果属于失败。运行时契约缺陷可以使端到端任务失败，但不能据此证明模型能力有缺陷。原因含糊时先保留未分类，等待调查。模型判分器可以评价可选的定性判据，但不能覆盖确定性失败或证据缺失。

预置解答的冒烟测试、允许协助的调试、自主评测分别记录。已声明的脚本用户轮次属于任务内容。人或更强 agent 提供选择器、代码或修复提示属于技术协助。出现协助时保留原尝试，将新尝试标为受协助；不能用修复后的成功覆盖失败。agent 自行修复仍属于自主，但消耗同一次尝试预算并被计数。

### 泛化与比较

调优前按页面结构和任务家族划分场景。Hacker News 等已经用于修复的页面归入开发集。保留一个未参与调优的结构家族和后续真实站点检查。同一模板仅改 CSS 类名属于稳健性检查，不是独立泛化证据。保留用例一旦为修复提供信息，就移入开发集，下一版本选择新的保留用例。

使用小型覆盖矩阵，避免完整笛卡尔积：表格、列表、卡片布局；重复或误导区域；嵌套标题与链接字段；延迟内容及使文档身份更新的导航；重复链接与更新、停止行为。起步采用两个开发结构家族、一个保留家族和选定扰动。公布逐家族样本数与结果；小规模试点不能建立总体成功率。

分别比较强能力基线、具有相同工具和 skill 暴露的 v4-flash、使用拟议通用帮助的 v4-flash。每次改变一个因素，保持初始状态和判据，记录模型与版本、skill 摘要和工具契约摘要。如果基线使用不同执行器或工具范围，则报告为系统比较，不能将全部差异归因于模型。运行前声明重复次数、质量下限、可接受回归及比较规则，保留包括失败和取消在内的全部尝试。没有预先声明的门槛或样本不足时，只发布观察结果，不作晋级决定。

允许刷新失效页面身份、阅读工具 schema、检查页面区域、核对外部效果等通用指导。拒绝伪装成 skill 的站点答案、固定选择器、预写插件解答以及接受实现方自述的判分逻辑。既评估增加护栏，也评估移除护栏：仅当保留集质量或消耗改善，且其他方面没有不可接受的回归时才保留。Eval 提供声明矩阵内的泛化证据，不保证下一次任务一定成功。

### 效率与预算

分别报告首次成功、最终自主成功、受协助成功、未解决结果、自行修复次数和技术干预次数。展示端到端耗时及模型、工具、准备、验证耗时；这些时段可能重叠，没有统计规则时不得直接相加。报告输入、输出、缓存 Token，请求数（包含重试和委托模型调用），浏览器操作数及证据大小。测量缺失保持未知，不填零。

执行前声明请求、Token、总时长及浏览器操作上限。复用已获批准的运行时预算权威，在派发时强制执行，不新增 Eval 专用估算器。插件触发和委托调用属于同一用例消耗范围。如果组合后的运行时无法强制执行必需上限，真实执行预检失败并给出可采取行动的原因。为清场预留有上限的额度；执行额度耗尽即停止接纳。正常预算执行导致任务未完成时，完成判据为失败，原因是 `budget-exhausted`；操作人取消与预算遥测丢失仍是不同的不确定原因。

Token 是观测用量，金额是可选估算，须注明 provider、币种、价格版本与时间戳。无法获取权威价格时，金额显示未知。分别展示 agent、辅助方、验证方、失败尝试及准备成本，避免通过隐藏协助让便宜模型显得更便宜。每个自主成功任务的成本，以声明的比较组总消耗（包括失败尝试）为分子、自主成功数为分母；零成功时不产生有限值。同时展示成功比例与样本数，不能只按 Token 单价选择胜者。

通过无模型调用的预检、用于诊断的针对性失败复查、有上限的证据采集及不可变构建复用，降低迭代成本。复查属于诊断运行，不能替换原评分样本。浏览器隔离和回放绑定支持安全并行前，推迟多单元并发；起步试点采用容易解释的顺序证据。

### 真实执行与回放

真实执行检验当前模型和浏览器行为。快照回放检验已录制会话契约。对浏览器证据包重新判分，检验检查器对所记录事实的判断。这是三种不同结论，在报告中分别展示。回放与重新判分均不能证明新 agent 能再次识别页面，也不能证明今天的真实站点仍然可用。

首个浏览器增量支持真实执行，以及对冻结证据的确定性重新判分。完整浏览器动作回放需要已捕获、可控的环境，暂缓实现。明确记录这一限制，不从会话日志编造浏览器回放。判定器修复后，可以在新判定器摘要下对旧的完整证据重新判分，同时保留原判定；模型行为变化需要新的真实尝试。

## 考虑过的替代方案

**单独建立浏览器评测工具。** 这会重复路线统计、保守结果分类、报告及后续集成。适配器扩展既有所有者，并将浏览器特有细节保留在自身。

**只向现有用例添加选择器和浏览器断言。** runner 仍要求先有回放 fixture 和单段提示词，还会把人工环境准备与协助排除在评分用例之外。执行类型和生命周期必须一起变更。

**先建立通用工作流 DSL、观察器注册表及判分平台。** 一个浏览器试点不足以支撑这些抽象。类型化适配器载荷及每次尝试一次执行器调用已覆盖具体需求；只有第二个真实消费者证明复用价值后，才提取共享机制。

**让 agent 报告或模型判分器成为验收权威。** 页面错误或清理不完整时，两者都可能接受可信的叙述。独立观察的确定性检查仍为必需；定性判分作为补充。

**用站点专用 skill 保证成功。** 这类 skill 可以作为有用的产品配置，但会改变评测结论的范围。将它与保留页面的自主识别分开，计入维护和辅助消耗。

## 验收条件

实现分为四个有明确边界的增量。本次文档 PR 不完成其中任何运行时验收。

| 增量 | 可观察验收 |
| --- | --- |
| 契约与编写 | Version 2 校验两种执行类型；既有快照用例判定保持；未知类型和不支持模式在预检失败；单用例试跑展示失败检查点与证据 |
| 浏览器生命周期 | 随仓库交付的模板在隔离环境执行创建、点击、更新、停止，并有独立断言；受控错误链接、重复项、残留按钮、丢记录、取消和观察器丢失分别产生规定的失败或不确定结果 |
| 信任与可移植性 | 被测方不能读取或修改验证预期；换页仅需改变用例与环境数据，不修改核心；必需证据篡改被拒绝；清场不能掩盖产品清理失败 |
| 比较试点 | 全新的强能力基线与 v4-flash 尝试使用已声明配置、保留家族、重复次数与预算；报告保留原始失败、协助、未知值、逐家族结果，并区分真实执行与重新判分 |

评测系统就绪与每个被测模型都通过是不同的结论。正确识别 v4-flash 失败可以满足评测验收；缺少独立证据的绿色报告不可以。干净 checkout 必须只依赖已文档化的凭据和浏览器前提运行公开单用例路径，不依赖私有修复脚本或手改存储。更大的 Epic 保留其独立的多用例、恢复及部署义务。

## 风险

真实站点会变化，浏览器自动化可能独立于 agent 失败。受控 fixture 与明确的不确定性有助于解释比较，但不能消除外部波动。用例多样性不足仍会过拟合；逐家族报告与保留集轮换使结论边界可见。

丰富的观察会增加延迟、存储及潜在数据暴露。限制采集规模、遮蔽秘密并明确保留责任方。插件触发调用与异步清理可能逃过简单统计；声称已强制执行预算与清场前，必须通过真实组合运行时证明其行为。

Schema version 2 会改变评测持久格式与报告消费者。原子迁移仓库拥有的示例和消费者，对不支持的旧输入明确报错。浏览器 API 细节归适配器实现所有，必须对照实际目标版本核验；本提案不冻结开发 worktree 中的选择器或签名。
