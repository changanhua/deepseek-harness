# 查重与创建

## 任务输入

明确仓库根 URL、完整标题和正文。用户要求只用浏览器时，遵守指定通道。登录或人工验证需要用户完成时停下。

## 可复用流程

1. 在目标仓库 Issues 搜索 `is:issue in:title "完整标题"`，覆盖 open 和 closed。搜索语法中的标题引号需转义或改用足以覆盖目标的宽查询再逐项比较。返回行的标题必须逐字比较；部分结果、未加载完成或仅显示 open 的结果不能证明没有同名 Issue。
2. 若找到同名 Issue，读取详情确认仓库和标题并返回链接。否则保留本次搜索的仓库、标题、完整查询、覆盖范围、结果和读请求来源。
3. 打开新建页后重新读取并绑定标题、正文和提交控件。向唯一匹配的字段填入请求值；允许从同一观察复用仍有效的两个字段引用，执行器负责拒绝失效引用。
4. 一次显式值回读核对仓库、标题、正文。`valueRedacted`、`valueTruncated` 或缺少 `value` 都不能视为核对通过。填入回执只证明输入操作，不能替代回读。
5. 提交一次。结果未知时查询原 `requestId` 并读当前页面；不再次派发提交。验证错误、未完成导航和未知结果均不能推导已创建。
6. 新读详情页，核对仓库、标题和正文后返回链接。既有任务验收只能证明其实际表达的条件；“无重复且只派发一次”还需要对应搜索证据和操作记录。

## 证据与升级

导航后重新绑定操作引用。搜索事实仍可作为此前在指定仓库、查询和授权范围下的历史证据；根据任务时效要求和外部变化判断是否重查。登录身份、授权或用户目标改变后，先由现有任务机制处理变化。

页面模型不匹配、重复控件或搜索覆盖不明时，带上该页观察和已完成阶段交给通用 Agent；不为了满足模板而猜测。模型中的动作含义不替代本次用户授权。单次浏览器派发也不保证外部服务的唯一创建语义。

收到 `journal_capacity` 时保留已完成阶段。若回执明确携带 `value.admission.executed: false`，本次被拒绝的输入尚未执行；`recheckAt` 非空时可等待到该时间后重新观察，但它不预留容量。null 时不能只凭等待推断恢复。遵守同一任务的截止时间与预算；恢复后先读取当前页面并重新验证条件，再决定是否发起新的操作。其他未知结果仍按原请求查询，不能套用此规则重复提交。完整语义见[扩展连接行为](../../../../apps/chrome-extension/README.zh.md#连接行为)。
