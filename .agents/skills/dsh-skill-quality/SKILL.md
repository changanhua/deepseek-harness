# Skill 衡量标准

由用户手动发起，例如“评估 dsh-reuse 是否有实际价值”。评估实际工作的变化，不以文档规范、步骤服从或节省 token 代替质量。允许模型参与试验和评判；skill-creator 只是编写参考。评估请求不授权子代理，遵守用户的单独代理使用约束。

## 1. 独立定义成功

从用户需求和当前产品契约确定案例的输入、起始环境、必需结果、允许的不同解法、不可接受的副作用及证据，不从待测 Skill 反推答案。先验证已知正确结果能通过、已知错误结果会失败。准备真实代表性任务、历史失败和未用于修改 Skill 的保留案例；覆盖困难、普通及不适用任务。历史失败可证明回归修复，不能独自证明泛化。素材见 [cases.md](references/cases.md)。

## 2. 分维度衡量

每项分别给分并附证据；无法观察记“未知”。这些锚点描述一次试验，不证明 Skill 的贡献，禁止简单加权为一个总分。

| 维度 | 0：不合格 | 1：部分有效 | 2：达到要求 | 证据 |
| --- | --- | --- | --- | --- |
| 任务结果 | 目标未实现、结果错误或破坏已有能力 | 部分完成，需实质返工 | 达成预先定义的结果，无重要回归 | 产物、实际运行状态、独立验收 |
| 判断质量 | 关键判断错误、无依据或机械套规则 | 方向基本正确，但漏掉重要取舍 | 识别决定性问题，判断有据且适合任务 | 判断依据及后续结果 |
| 范围与自主性 | 擅自设限、越权、偏离目标或被流程卡住 | 多余流程，需要用户拉回 | 保持目标，跳过无关步骤并完成授权工作 | 执行记录、纠正、无关改动 |
| 可靠性 | 重跑或合理变体频繁发生实质错误 | 试验和变体表现混合 | 已测任务及变体上稳定达到要求 | 全部试验、失败分布，不只最好一次 |
| 当前适用性 | 核心规则与当前代码、工具或权限冲突 | 非核心条款过时，修正后可用 | 关键规则与当前环境一致 | 当前契约和工具行为，日期或哈希不能证明 |
| 副作用 | 引入重要缺陷、误报、无关架构或错误完成声明 | 有可恢复干扰或额外返工 | 未观察到实质负面影响 | 差异、误报、遗漏和返工 |

## 3. 对照判断增益

同一任务比较“不加载该 Skill”和“加载该 Skill”，修改时再比较旧版。固定模型、推理设置、工具、其他指令和起始数据；使用不泄露答案的干净上下文。记录实际加载内容，防止无 Skill 基线通过其他提示获得相同规则。历史记录条件不一致时只作诊断，不声称受控归因。

对照最终产物和完整执行记录，按任务阶段找关键差异：新增有效判断、纠正错误、无明显影响、错误锚定、过度规划、无关产物、阻碍交付。归因必须指出条款、行为和后果；行为变化不等于改善。

先少量试验定位明显问题，再重复不稳定或影响结论的案例，保留全部结果与样本数。按任务类别报告胜／平／负、分维度质量及不确定性。不能用单次成功证明稳定，也不能把所有任务混成平均分。执行真实外部写入不能为对照而重复，使用隔离夹具。

时间、token、工具调用只是辅助观察。质量不足不能因便宜而算成功；为可靠结果增加必要研究与验证可以值得。仅在质量与风险可比时用成本差异做取舍。没有实际运行就写“标准已制定，效果未验证”。

## 4. 可量化结果与完整覆盖

每次报告先展示可观察产物和计数，再给解释性评分。通用计数、每个 Skill 的专属指标及全部 `dsh-*` 覆盖清单见 [measurement-matrix.md](references/measurement-matrix.md)。检查当前目录与清单是否对应；新增 Skill 不因清单未更新而被静默排除。使用频率必须来自可核对的调用记录；没有记录时只能按影响估计优先级，不能声称“使用最多”。

以下三个是具体例子，不是范围上限：

| Skill | 价值假设 | 关键测量 | 无效替代指标 |
| --- | --- | --- | --- |
| dsh-reuse | 改善复用、改造或新建的架构选择 | 能力识别正确性；推荐是否满足需求；后续返工；同时测适合复用和必须新建的案例 | 搜索次数、候选数量、总是复用、报告长度 |
| dsh-code-review | 发现真实缺陷且不误报 | 已知缺陷召回、可复现结论、误报、修复建议有效性；严重与轻微缺陷分开 | 评论数量、风格意见、未经核实的自评 |
| dsh-change-verification | 准确区分完成与未完成 | 缺陷版本是否拒绝、正确版本是否通过、用户承诺覆盖、错误放行及无依据阻塞 | 测试数量、跑满所有层级、证据表数量 |

已知缺陷集不等于全部真实缺陷；新发现先复现再纳入真值。结果和评分标准应允许合理的替代实现，不要求照抄 Skill 步骤。

## 5. 校准裁判并形成结论

能执行的结果用独立检查；开放式判断可由模型按锚点评分，但要引用证据、允许未知，并用人工样例校准。对比时尽量隐去版本、交换呈现顺序，检查偏爱长答案的问题。评分冲突先检查标准与证据，不能直接平均。作者或生成答案的模型自评不得作为唯一裁判。

结论按任务类别给出：保留、缩小适用范围、修改复测、移除或证据不足。重大越权、错误交付和重要回归不能被其他高分抵消；未观察到增益不等于立即移除，但不能声称有效。报告包括案例、基线与候选身份、分项证据、成对差异、失败、局限及建议。

模型或环境变化后，原结论只适用于原条件，是否复评由用户决定。该流程没有定时任务或日常检查入口。

公开评测可以直接用于筛选风险和改进方向，但必须记录被测 Skill、版本、模型、运行框架、场景数及是否公开逐项结果。名称相似不等于结论可转移；只有聚合分、没有场景明细的结果属于弱证据。首批外部证据应用见 [external-evidence-first-batch.md](references/external-evidence-first-batch.md)。

## 方法来源与边界

- [OpenAI：Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)：定义任务成功，保留执行记录及产物。其步骤检查仅适用于必需操作，不扩展成流程服从评分。
- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：区分结果与执行记录，组合并校准代码、模型和人工判断，覆盖正反案例。示例的全部评分器不是必选项。
- [Counterfactual Trace Auditing of LLM Agent Skills](https://arxiv.org/abs/2605.11946)：成对分析有／无 Skill 的行为影响，弥补只看成功率的不足。该研究不是三个 DSH Skill 的效果证明。
