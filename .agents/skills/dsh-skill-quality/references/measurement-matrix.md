# 可见结果、计数与覆盖清单

本表是评估规范，不是已执行的成绩单。范围包含当前全部 22 个 `dsh-*`，其中 21 个业务／工程 Skill 和本评估 Skill。每次手动评估先核对当前目录；按用户指定范围执行，未运行的项明确列出。先按交付影响与失败后果排序；没有调用记录就不编造使用频率。

## 每次报告首先展示这些数

| 指标 | 计算或记录方式 | 必须避免的误读 |
| --- | --- | --- |
| 实际任务完成 | 完整达到预设结果的任务数 / 已执行任务数；同时列中断和未执行数 | 局部检查通过不等于任务完成；环境故障单列，不偷偷删掉 |
| 验收覆盖 | 有实际证据支持的必需结果数 / 预先定义的必需结果数 | 不以 Skill 自己增加的步骤充当分母 |
| 已知缺陷检出 | 被正确定位并核实的缺陷数 / 预置或已核实缺陷数，按严重性分别列 | 一个缺陷的多条评论只算一次；未知全集不声称完整召回 |
| 发现可信度 | 已核实真实问题数 / 已核查问题数；未核查数单列 | 未核查不计为真，也不直接计为假 |
| 错误放行 | 被宣称完成但未通过预设验收的次数 / 所有完成声明次数 | 没有完成声明时记不适用，不能伪装为 0% |
| 错误阻塞 | 无契约或证据依据的阻塞次数 / 已核查阻塞次数 | 真正缺少授权或条件不能算错误阻塞 |
| 回归与越权 | 重要回归、WIP 损失、越权动作各自计数并列事件 | 不允许用其他高分抵消 |
| 用户救场 | 为纠正事实、范围或操作错误而介入的次数 | 用户新增需求和正常回答必要问题不算救场 |
| 返工 | 因错误决策撤回／重做的步骤及产物，逐项列出 | 合理试验失败不自动算浪费 |
| 配对增益 | 相同案例有／无 Skill 的胜、平、负和各指标差值 | 必须同时展示基线与候选原始计数，不能只给百分比 |
| 稳定性 | 每个案例每次试验的成功／失败矩阵及样本数 | 不只保留最好的一次；少量试验不宣称统计保证 |

总结果优先使用任务级统计，验收项是诊断明细，避免细分很多简单检查淹没一个关键失败。对开放式质量仍保留有证据的人工或模型判断，不为凑数字制造假的精度。未核查、未知、不适用、未运行严格分开。

## 应当直接交给用户看的证据

每个案例展示“要求 → 基线产物 → 使用 Skill 后的产物 → 验收结果”，附可打开的文件、diff、页面、运行记录或缺陷复现。失败直接标到证据位置。长执行记录仅提供入口与关键片段，不能用日志堆积代替结论。

示意，非实测：一个含 5 个已知缺陷的审查案例，基线发现 2/5、误报 1 项；候选发现 4/5、误报 3 项。应展示新增检出的两个缺陷和三个误报，判断严重性与实际影响，不能因发现数更多就宣布候选胜出。

## 评估方法自身也接受检查

`dsh-skill-quality` 使用已知正确、错误和合理替代解的样例校准：统计误判，检查同一证据换顺序／隐藏版本是否改变评分，检查能否从证据重建结论。不得因作者写了本标准就豁免本 Skill。这里的校准不自动启动递归评估。

## 怎样决定合格

每个案例先定必需结果和不可接受错误，不事后移动标准。已知越权、WIP 损坏、伪造证据或重要回归使该案例失败。其余差异按真实影响判断并注明范围，不设置来源不明的统一 80 分门槛。需要长期通过率承诺时，另行确定有代表性的案例数量、重复次数及可接受失败水平；当前不能以小样本冒充长期保证。
