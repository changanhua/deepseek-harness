# DSH Browser Assistant

English | [中文](README.zh.md)

This is the Manifest V3 DSH Browser Assistant, requiring Chrome 116 or later; its version is declared in [manifest.json](manifest.json). It replaces the former capture-controller entry point with a session side panel. Build an unpacked installation with `pnpm run build:chrome-extension`; root build dependencies pin `puppeteer-core` 24.31.0 and `esbuild` 0.28.1, generating `vendor/puppeteer.js`.

## Use the side panel

Connection recovery uses browser lifecycle events, not indefinite polling. A transient disconnect permits five credential-free HTTP probes with 1, 2, 4, 8 and 16 second backoff; a WebSocket is attempted only if the service responds. After that, the channel pauses. Browser startup, extension update, a successful top-level navigation to the configured service, a newly visible sidebar, or the sidebar's network-online event can trigger one recovery attempt with the saved credentials. Concurrent events coalesce, and a persisted ten-second cooldown prevents event storms and worker restarts from repeatedly probing. A stable connection resets the short retry budget. Explicit disconnect and revoked credentials do not reconnect automatically. A server that recovers silently while no browser event occurs waits for the next event or “重试连接”; there is no background polling fallback. Recovery never replays page input or creates another pairing.

Browser actions can return bounded transition observations: the source page, a freshly verified page in the same tab, and up to eight candidate child tabs. A child relationship does not prove which input opened it and never selects it automatically. Observers stop on cancellation or the request deadline; the post-action observation window is at most 250 ms and does not cover later events. Both forms of explicit tab opening create background tabs and return a complete browser-session tab reference.

The same extension can connect to Codex independently from DSH. In “连接与设置”, select “连接 Codex” after installing the standalone browser connector at `http://127.0.0.1:3091`. Ask Codex to read or operate the desired page; DSH need not be running. Each connection has its own credentials, replies, and disconnect handling. Both share one browser execution journal so unresolved writes cannot compete on the same tab. The extension's chat and reading controls continue to use DSH.

When Reading is disconnected, an inline connection card accepts the DSH address and uses the existing connection flow. Initial setup, pending connection, and temporary offline states have distinct messages. Empty reading controls stay hidden until connected; existing readings remain available. A saved offline connection keeps its grant while reconnecting.

Reading selects a model and supported reasoning effort independently from chat. The list comes from every configured DSH provider, including compatible custom routes. “DSH 完整设置 ↗” opens the complete settings panel at `/#settings=models` for providers, API addresses, credentials, model lists, and other DSH settings. Credentials remain in DSH; the extension stores only its reading selection. Refresh the model list after configuration.

The extension sidebar has internal “对话” and “解读” tabs. Reading uses the sidebar's main area for AI replies, hiding the composer, capture controls, and authorization banner. It supports adjustable text size, recent-answer selection, and live updates. Conversation restores the original chat interface. Switching views does not create a browser tab or leave Zhihu.

Question-and-answer cards and Zhihu-column article cards in the recommendation feed offer “AI 总结解读” at the far right of its bottom action row. Clicking opens the existing sidebar and switches directly to its internal reading tab, expands and reads that answer on the current Zhihu page, and sends one independent request through DSH model adapters. It creates no Session and includes no chat history or tool schemas. The last 30 readings are stored in the extension for display only and never sent as subsequent context. Reading follows the latest generated content without navigating away. Newly loaded cards also receive the link. After sending, “已发送 · 查看解读” shows reading without submitting again. The analysis request identifies incomplete expansion, truncated text, and images not captured. Refresh Zhihu after reloading the extension to enable the entry.

Open the side panel from the toolbar or with Chrome's `Alt+Shift+A` command. Once connected, the first send automatically creates a DSH Session using DSH's default Agent preset; you can also select an existing Session. When sending is blocked, the composer shows the reason and retains the draft. Select text on an HTTP(S) page and use “用 DSH 讨论选中文字” to add it to the draft. “正文” captures the loaded page body; the side panel previews it, selected text, and real Chrome screenshots before the user sends them. It can also stop or resume the selected Session and open that same Session in the Web application.

ChatGPT replies, Zhihu answers, and Zhihu articles also expose “采集到 DSH 内容库” in their page action rows. The extension validates the current page identity, sends explicitly selected content to Content, and shows the import state on both the page and the sidebar's current-capture area. After success it opens the DSH entry; failures, disconnects, and unknown results keep the original request for explicit recovery and never silently resubmit it. Chrome stores only capture bindings and receipts; DSH owns content persistence and later organization.

Content-library import authorization is shown separately from assistant-session authorization. The sidebar explicitly reports whether the content library is connected, so an assistant connection cannot be mistaken for a completed content import.

Body capture prefers the page's main or article region and preserves its URL, title, document identity, and capture time. It excludes editable fields, hidden content, navigation, comments, and controls. Collapsed or still-generating content is omitted and reported as incomplete; the extension does not expand it. Capture stops at 48,000 text characters or 10,000 visited nodes and labels truncated results. A replaced document or a different foreground tab when capture finishes rejects the result. At most three context items can remain in the draft, within a combined 5 MiB limit.

The default DSH address is `http://127.0.0.1:3080`. Personal deployments request read, write, and observation access to all HTTP(S) websites together with Session interaction on connection. The address and grant persist until revoked, without per-site or per-action confirmation. Existing limited grants can be upgraded once with “永久授权所有网站”. Only a different port or server needs an address change. An address must be an HTTP(S) origin root, without a deployment path prefix.

The manifest requests all HTTP(S) website access, `activeTab`, `debugger`, `webNavigation`, side-panel support, and the selection context menu. Reload an existing unpacked installation after updating so Chrome applies the `debugger` and `webNavigation` permissions; Chrome's own restrictions still govern internal browser pages. Screenshot capture still uses Chrome's `activeTab` capability. The `Ctrl+Shift+7` global shortcut opens or focuses an independent assistant window while Chrome is running, including when another application has focus. The settings button opens the same window, bound to the same Session as the sidebar; Chrome shortcut settings allow reassignment. Collection is never submitted automatically; capture actions are registered on supported pages and send only after an explicit click. Tokens and verifiers remain in trusted extension storage and never reach page scripts.

## Browser operation engine

The extension bundles Puppeteer's browser-side public experimental `ExtensionTransport` and connects it to the current logged-in Chrome tab through `chrome.debugger`. Its transport approach follows [Nanobrowser](https://github.com/nanobrowser/nanobrowser), without adopting Nanobrowser's agent loop, model integrations, or interface. Puppeteer is the default engine and executes every implemented action: `click`, `fill`, `submit`, `double_click`, `right_click`, `hover`, `press`, `select`, `check`, `drag`, `upload`, `navigate`, `back`, `forward`, `reload`, `tab_open`, `tab_close`, `tab_focus`, `scroll`, `wait`, and `screenshot`. The DOM compatibility engine retains only the earlier `click`, `fill`, `submit`, `navigate`, `scroll`, and `wait` actions; requests for the newer actions fail explicitly. After a first mouse or key press is issued, stop allows its matching release, reports `unknown`, and never promises to undo an in-flight operation.

Snapshots include each control's label, role, viewport state and nearby card/section heading. A `tree` snapshot pages the full Document, element, text, and open Shadow Root hierarchy from one stable cache; every node keeps a stable index and parent index, and a returned cursor reads the next page without rematching nodes. Iframe elements mark their source boundary, while iframe documents remain separate frame reads. The tree omits hidden, editable, script, and style text, and it keeps hidden structure without exposing its label or text. Trusted task snapshots also carry bounded mount/text presentation queries through the executor to the isolated page runtime; each answer is tied to the exact Session, installation, grant epoch, page, and still-connected panel instance rather than matching arbitrary page text or a forged mount attribute. The [browser tools](../../packages/browser/tool-browser/README.md) provide model-facing budgets and fresh feedback after actions. A screenshot is limited to the main frame and 400,000 base64 characters; a background target uses the focus-free Puppeteer path or fails explicitly instead of activating the user's tab. Upload accepts up to 16 absolute paths only when the current user message names each exact path; the tool checks that source before execution and does not add a separate approval dialog.

Control snapshots with `query` restrict text and structure to the returned controls' local containers; `textScope` distinguishes that evidence from whole-page text. The independent [MCP connector](../../packages/mcp/browser-extension-mcp/README.md) can explicitly request current input/textarea values for submission checks. Default and background observations omit these values. Password/file/hidden and autocomplete-marked credential/payment values remain excluded; truncated values cannot prove a complete match.

Clicks use the exact control's clickable point after the driver has scrolled and checked its stability and hit target. The mouse input retains per-packet authority checks and does not wait again for a viewport observer, whose callback can be suspended in a background tab.

When a completed click or key press replaces its document before feedback is read, its receipt acknowledges only the completed input and marks the feedback unavailable. The transition observation identifies the replacement for a fresh read. Interrupted input, revocation and lost fill verification remain unknown; the executor never infers business success or replays input.

Tab listing includes a complete `tabId`, `windowId`, and `browserSessionId` reference for each authorized tab. A snapshot with `expectedTab` checks that reference before and after capture and returns the verified `tab`; a moved or replaced reference fails instead of selecting another page. Caller-side task scope and child selection remain outside the extension.

## Background monitoring

Open “监控” after connecting, without another site grant. A plan belongs to the currently selected Session and the displayed page URL. Choose one check or a recurring interval, a text-change or text-match condition, and whether missed periods should be coalesced or skipped. The Host stores the plan and runs each finite check through Queue while the sidebar and Web are closed.

The toolbar badge counts pending Host notifications. The worker refreshes them on connection and every 15 seconds; the sidebar displays each durable notification id once until “已读” acknowledges it. Opening its Session uses that monitor's original owner, regardless of the foreground page. Pause stops subsequent checks; resume explicitly binds current observation authority. A lost creation response retains the original request id, Session and URL across worker restarts for “重试原请求”. No second task or notification database is created in Chrome.

## Browser activity

After granting observation access, open “活动”, choose the sites, event kinds, sampling interval, text limit, and retention limits, then explicitly save into the current Session. The collector observes focused normal windows only and checks durable Chrome site permission before and after capture. Temporary `activeTab` access alone cannot enable it. Text defaults to zero characters; continuous activity does not capture images. Page observers retain only a dirty flag and expire without renewal.

“暂停采集” stops local collection before awaiting the Host. A confirmed pause survives Chrome and Host restarts; “保存并开始（当前会话）” explicitly resumes. Configuration is unavailable until the current connection's policy is synchronized. A known revision conflict releases that rejected request but persists a local hold until another explicit save; unknown outcomes retain their original request identity for confirmation.

Chrome buffers at most 32 memory events and one persisted batch of at most 32 events, with encoded byte limits. Overflow and policy invalidation are counted as discarded events. A last-batch retry retains its original id and sequence; it does not create duplicate Host events. “检索 DSH 活动” searches Host-owned history under current site and grant authority. Raw activity is separate from [monitor summaries](../../packages/browser/browser-monitor/README.md) and curated knowledge.

## SiYuan knowledge handoff

For a deployment using the local native SiYuan MCP server, explicitly load [the optional connection patch](dsh-siyuan.cordis.patch.yml) with the selected `dsh web` Profile. It reuses the existing MCP client at `http://127.0.0.1:6806/mcp` under `serverName: siyuan`. If the deployment already has that namespace, reuse its connection instead of loading another instance. The patch does not start SiYuan or configure its notebooks. The shared `siyuan-knowledge` Skill supplies the user's library map and writing conventions.

In “活动”, enter a filter, choose “提炼知识” or “整理资料”, then select “整理并保存到思源”. This submits an explicit save request to the same Session. The Agent searches that Session's retained activity, distinguishes observed source facts from interpretation, checks existing notes, then writes a relevant summary and verifies it through native MCP readback and search. A stable source marker helps avoid duplicates; an unavailable connector cannot be reported as a completed write. The MCP connection controls available tools; library destinations and non-destructive writing remain Agent workflow conventions, not a new per-action access-control system.

## Recovery and history

Chrome keeps an immutable pending submission or `pendingCreate` binding while it is offline or restarts. A create retry keeps its fixed Session id; a submitted request keeps its caller-minted id and becomes `unknown` when its receipt is lost. Reconnection recovers status and the follow cursor without replaying input. The Host Session owns the complete message history; Chrome stores only its binding and pending state, retains at most 1,000 in-memory records or 2 MiB, and opens the same Web Session hash when requested.

When updating an unpacked installation, reload it on Chrome's extensions page. Review any permissions Chrome presents, then open the toolbar on a tab before capturing a screenshot. Old content-library records and stored data remain intact; page capture actions and the sidebar current-capture area use the same receipt.

## Connection behavior

When retained execution receipts fill the journal, a `journal_capacity` rejection includes `value.admission.executed: false` and `recheckAt`. The timestamp is the earliest retained quiescent write expiry in Unix milliseconds; it suggests when to recheck and reserves no space. `null` gives no time-based recovery promise. After expiry, a new admissible read can resume in the same installation. Requests that may still execute remain protected regardless of time; an unknown outcome never authorizes repeating an input.

The worker streams a first snapshot and later cursor-addressed events for the selected Session. A visible same-Session peer with `session:interact` can receive a browser-action card through the existing Approval answer chain; hidden or disconnected peers delegate to Web, and cancellation or timeout removes the card. An unknown action persists its minimal identity, outcome, and quiescence fact without human confirmation: the tab stays claimed only while the operation may still be running, and a proven-quiescent result releases the claim while remaining queryable, so a later connection can still synchronize it. Site-login and real-model acceptance depend on the configured deployment. The extension does not manage Chrome profiles or replace the DSH Web application's session history.
