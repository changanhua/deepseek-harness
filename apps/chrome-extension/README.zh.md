# DSH 浏览器助手

[English](README.md) | 中文

这是 Manifest V3 的 DSH 浏览器助手，版本为 0.3.0，要求 Chrome 116 或更高版本。它以会话侧栏替换原收藏控制器入口。加载解压版前运行 `pnpm run build:chrome-extension`；根构建依赖固定 `puppeteer-core` 24.31.0 和 `esbuild` 0.28.1，并生成 `vendor/puppeteer.js`。

## 使用侧栏

解读页未连接时直接显示连接卡片，可填写 DSH 地址并使用现有连接流程。首次配置、等待连接和临时离线分别显示对应提示。连接前隐藏空的阅读控件，已有解读仍可查看；临时断线使用已保存的授权重连。

“解读”页独立选择模型与支持的推理强度，列表来自 DSH 已配置的全部服务商，包括兼容接口的自定义模型。“DSH 完整设置 ↗”通过 `/#settings=models` 打开完整设置面板，可配置服务商、API 地址、密钥、模型列表及其他 DSH 设置。密钥保留在 DSH，扩展只保存解读模型选择；配置后可刷新模型列表。

扩展侧栏内部提供“对话”和“解读”页签。“解读”使用侧栏主区域显示 AI 回复，隐藏输入区、采集按钮和授权提示，支持调整字号、切换近期解读及实时更新；“对话”恢复原聊天界面。切换页签不会创建浏览器标签页，也不会离开知乎。

知乎推荐流的问答卡片和专栏文章卡片在底部操作栏最右侧提供“AI 总结解读”。点击后打开原侧栏并直接切到内部“解读”页签，在当前知乎页面展开并读取该条回答，通过 DSH 模型适配器发送一次独立请求，不创建会话，不包含聊天历史或工具定义。最近 30 条解读保存在扩展中，仅供查看，不会作为后续上下文发送。解读自动显示最新生成内容，不跳转页面。追加加载的卡片也会显示入口。发送后链接变为“已发送 · 查看解读”，再次点击只显示解读，不重复提交。未完全展开、达到文字上限或包含未采集的图片时，分析请求会说明材料范围。更新扩展后刷新知乎页面使入口生效。

从工具栏打开侧栏，或使用 Chrome 的 `Alt+Shift+A` 命令。在其中选择或创建一个 DSH Session，然后在 HTTP(S) 页面中选中文字并使用“用 DSH 讨论选中文字”加入草稿。“正文”采集已加载的网页正文；侧栏在用户发送前预览正文、选区和真实 Chrome 截图。它也可以停止或恢复所选 Session，并在 Web 应用中打开同一个 Session。

正文采集优先读取页面主区域或文章，保留 URL、标题、文档身份和采集时间。编辑区、隐藏内容、导航、评论和操作控件不会进入正文。折叠或仍在生成的部分会跳过并提示不完整，扩展不会自动展开它们。正文最多采集 48,000 字符或遍历 10,000 节点，达到上限会标明截断。目标文档被替换，或采集完成时前台标签已经改变，会拒绝结果。草稿最多保留三项上下文，合计不超过 5 MiB。

默认 DSH 地址为 `http://127.0.0.1:3080`。个人部署连接一次即申请所有 HTTP(S) 网站的读取、操作和观察权限，同时启用会话交互。服务地址和安装授权持久保存，直到撤销，无需逐站点或逐次操作确认。已有局部授权可点击“永久授权所有网站”升级一次。仅在使用其他端口或服务器时修改地址。地址必须是 HTTP(S) origin 根路径，不支持部署路径前缀。

manifest 请求所有 HTTP(S) 网站访问权限、`activeTab`、`debugger`、`webNavigation`、侧栏支持和选区右键菜单。更新后须重新加载解压版扩展，使 Chrome 应用 `debugger` 和 `webNavigation` 权限；浏览器内部页面仍受 Chrome 自身限制。截图采集仍使用 Chrome 的 `activeTab` 能力。Chrome 运行时，`Ctrl+Shift+7` 全局快捷键可打开或聚焦独立助手窗口，即使当前焦点在其他应用中。设置按钮打开同一窗口，并与侧栏绑定同一个 Session；可在 Chrome 快捷键设置中改键。扩展不会自动采集页面；旧有的三个动态页面注入脚本已经注销。令牌和 verifier 保留在扩展受信任存储中，绝不进入页面脚本。

## 网页操作引擎

扩展打包 Puppeteer 浏览器侧公开实验性 `ExtensionTransport`，并通过 `chrome.debugger` 连接当前已登录的 Chrome 标签页。传输方式参考 [Nanobrowser](https://github.com/nanobrowser/nanobrowser)，但不引入它的 Agent 循环、模型接入或界面。Puppeteer 是默认引擎，执行全部已实现动作：`click`、`fill`、`submit`、`double_click`、`right_click`、`hover`、`press`、`select`、`check`、`drag`、`upload`、`navigate`、`back`、`forward`、`reload`、`tab_open`、`tab_close`、`tab_focus`、`scroll`、`wait` 和 `screenshot`。DOM 兼容模式只保留早期的 `click`、`fill`、`submit`、`navigate`、`scroll` 和 `wait`；新动作请求会明确失败。首个鼠标或按键 press 发出后，停止会允许对应的 release 完成、报告 `unknown`，绝不承诺撤销在途操作。

快照包含每个控件的标签、角色、可视区状态及附近卡片或区块标题。`tree` 快照从一份稳定缓存分页返回完整的 Document、元素、文本和开放 Shadow Root 层次；每个节点保留稳定的 index 和 parent index，返回的 cursor 读取下一页而不重新匹配节点。iframe 元素标出 source 边界，iframe 文档仍通过独立 frame 读取。树会排除隐藏、可编辑、script 和 style 文本，并保留隐藏结构而不暴露其标签或文本。[浏览器工具](../../packages/browser/tool-browser/README.zh.md)负责模型可见的预算与操作后的新反馈。截图仅支持主 frame，base64 上限为 400,000 字符。上传最多接受 16 个绝对路径，且当前用户消息必须逐一写出准确路径；工具会在执行前检查该来源，不额外显示批准框。

## 后台监控

连接后打开“监控”，无需另行授权站点。计划归属于当前选择的会话和界面显示的网页地址。可以选择一次检查或周期检查、正文变化或文字匹配条件，以及补查最近一次或跳过错过周期。侧栏与 Web 关闭后，Host 仍会保存计划，并通过 Queue 执行每次有限检查。

工具栏角标显示 Host 待确认通知数量。worker 在连接时和每 15 秒刷新，侧栏按持久通知 ID 显示，点击“已读”后才确认移除。打开所属会话使用原监控的归属，不受当前前台网页影响。暂停会停止后续检查；恢复会明确绑定当前观察权限。创建回执丢失时，原请求 ID、会话和网页地址跨 worker 重启保留，可用“重试原请求”确认。Chrome 不另建任务或通知数据库。

## 浏览活动

授予观察权限后打开“活动”，选择站点、事件种类、采样间隔、正文和保留边界，再显式保存到当前会话。采集器只观察获得焦点的普通浏览器窗口，并在采集前后检查 Chrome 持续站点权限。临时 `activeTab` 访问不能单独启用它。正文默认零字符；连续活动不采集图片。页面观察器仅保留变化标记，不续租即到期停止。

“暂停采集”会先停止本地采集，再等待 Host。确认后的暂停跨 Chrome 与 Host 重启保留；“保存并开始（当前会话）”显式恢复。当前连接的策略尚未同步时不可配置。已知版本冲突会解除被拒绝的请求，但持久保持本地暂停，直到再次显式保存；结果未知时保留原请求身份用于确认。

Chrome 最多缓冲 32 条内存事件和一个最多 32 条事件的持久批次，并受编码字节边界限制。溢出和策略失效记入丢弃数量。最近批次重试保留原 ID 和序号，不会新增重复的 Host 事件。“检索 DSH 活动”在当前站点与授权范围内搜索 Host 持有的历史。原始活动与[监控摘要](../../packages/browser/browser-monitor/README.zh.md)及整理知识分开存储。

## 思源知识衔接

部署使用本机思源原生 MCP 时，在所选 `dsh web` Profile 中显式加载[可选连接补丁](dsh-siyuan.cordis.patch.yml)。它复用现有 MCP 客户端，以 `serverName: siyuan` 连接 `http://127.0.0.1:6806/mcp`。如果部署已有该命名空间，应复用原连接，不再加载另一个实例。补丁不启动思源，也不配置笔记本。共享的 `siyuan-knowledge` Skill 提供用户的库位映射与写入约定。

在“活动”中输入过滤条件，选择“提炼知识”或“整理资料”，再点“整理并保存到思源”，即可向同一会话提交明确保存请求。Agent 检索该会话的历史活动，区分观察事实与解释，核对已有笔记，再写入相关摘要并通过原生 MCP 回读与检索验证。稳定来源标记有助于避免重复；连接不可用时不能声称写入完成。MCP 连接决定可用工具；目标库与非破坏性写入仍是 Agent 工作流约定，不是新增的逐动作访问控制系统。

## 恢复与历史

Chrome 在离线或重启期间保留不可变 pending submission 或 `pendingCreate` 绑定。创建重试会保留固定 Session id；已提交请求保留调用方生成的 id，并在回执丢失时变为 `unknown`。重新连接只恢复状态和 follow cursor，不重放输入。完整消息历史由 Host Session 拥有；Chrome 只保存其绑定和 pending 状态，内存最多保留 1,000 条 record 或 2 MiB，并会在请求时打开同一个 Web Session hash。

更新已解压安装时，请在 Chrome 扩展管理页重新加载扩展。查看 Chrome 显示的权限后，在标签页中打开工具栏再采集截图。旧内容库记录和已存数据会保留，但其原收藏界面不是受支持的 UI。

## 连接行为

worker 为所选 Session 流式传送首个 snapshot 和后续按 cursor 寻址的 events。可见且同 Session、具备 `session:interact` 的 peer 能通过既有 Approval answer chain 接收浏览器操作卡；隐藏或断线 peer 委托 Web，取消或超时会移除卡。对于未知操作，journal 要求用户 acknowledgement 按钮后才持久化 `acknowledgementPending`，随后通过 `browser.acknowledge` 发送最小 identity、outcome 和完全停稳事实；后续连接可以再次同步它。真实登录站点与真实模型的验收取决于部署配置。扩展不管理 Chrome 用户配置，也不替代 DSH Web 应用的会话历史。
