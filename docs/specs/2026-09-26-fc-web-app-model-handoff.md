# FC Web App 应用模型与 Agent 自动化：Sol 落地交接

日期：2026-09-26（香港时间）。本文是面向实现者的设计与交接参考，描述已确认方向、当前证据和最小落地顺序；模型、Skill 与跨 Agent 验收尚未实现。本次交付仅写文档，由用户后续使用 Sol 推进。

## 目标与范围

让 Agent 通过轻量浏览器扩展理解并操作 FC Web App，将探索得到的页面、对象、动作、状态变化和失败经验保存成可复用的应用模型。Codex 与 DSH 的 Agent 能加载同一份模型，使用各自可用的浏览器工具完成任务。

FC Web App 是当前建模对象；SBC 是第一个业务闭环；“重大比赛”只是一次任务实例。模型允许继续积累俱乐部、阵容、转会等区域的知识，未探索的区域保持未知。完成其他业务需求不属于首个 SBC 闭环的前置条件，也不在本次文档中预设那些需求的执行范围。

用户已明确的方向：

- 扩展保持轻量，提供 Agent 使用的页面抓手；主要理解、规划与计算由 Agent 所在端承担。
- 先让 Agent 跑通任务，测到效率或可靠性瓶颈后，再把相关步骤提取为脚本或 DSH 服务。
- 普通页面切换无需逐次确认。
- 经验应跨 Agent 复用，不能围绕某一个 SBC 或固定关卡名称组织整个系统。
- 先交付本文，再由 Sol 推进落地。

## 职责划分

| 部分 | 责任 |
| --- | --- |
| 浏览器扩展 | 读取新鲜页面与控件引用、执行明确动作、返回结果及页面身份；维护已有执行器和请求日志。只有实际任务证明缺少抓手时，才补充有界的读取或操作能力。 |
| Agent | 根据用户目标选择相关模型片段，观察当前状态，决定下一步，调用工具并独立读回结果；处理模型未覆盖的页面和异常。 |
| FC 应用模型 | 保存页面识别方法、对象关系、动作语义、成功条件、适用范围和带证据的经验；为多个任务提供可组合的知识。 |
| 本地计算函数 | 处理组合搜索、约束检查等确定性计算。现有求解函数可作为候选实现；正确性及耗时需要实测。 |
| DSH | 复用已有 Browser、Skill 和 Session 能力承接工具、模型加载与必要的持久事实。新增运行服务以实际消费者和已观察瓶颈为依据。 |

首期可以由 Agent 直接读取仓库模型文件并调用现有工具。模型不会自行执行，也不等于另一个需要训练的神经网络。跨 Agent 传递的是显式知识、证据和工具使用方法。

扩展的业务逻辑应逐步收窄，但迁移现有全部模块不是首次现场试跑的前置工程。先确认哪些纯计算确有消费者，再移到 Agent 可调用的本地模块或 DSH 服务；一次迁移只保留一个计算事实来源。

## 模型的最小内容

下表是待实现的数据约定，不是已有 API。第一版可用 JSON 加简短 Markdown 表达，在实际操作中增补，不提前建立通用网站平台。

| 记录 | 必要内容 | 更新依据 |
| --- | --- | --- |
| 应用与适用范围 | 应用标识、知识修订、已观察的年份/语言/页面特征、证据日期 | 现场观察；无法确认的版本保持未知 |
| 页面状态 | 如何识别页面、主要对象、可用动作、列表/弹窗/选中态等上下文 | 当前页面证据及经过验证的识别方法 |
| 对象与关系 | 卡定义与库存实例的区别；卡实例、库存来源、阵容槽位、挑战等已需要的关系 | 真实读到的字段及任务需要 |
| 动作模板 | 语义目标、参数、前置条件、从新观察定位的方法、预期影响、成功读回条件、失败恢复方式 | 实际动作及其后续观察 |
| 经验条目 | 场景、预期、实际结果、证据引用、结论、适用范围、验证状态 | 成功与失败案例；猜测不能直接变成已验证规则 |
| 任务配方 | 用户目标、完成条件、要用到的页面/对象/动作与计算函数 | 业务需求；任务名称和参数属于实例输入 |

长期知识和实时观察分别保存。`tabId`、`documentId`、`snapshotId`、`elementId`、本次库存、余额与当前完成状态属于有时效的观察，不能作为下次执行的固定参数。动作使用当前仍有效的页面引用；文档或控件变化后重新观察和定位。

每个实时事实应带来源、观察时间和覆盖范围。读取 313 条记录只证明读到了这些记录；列表遍历结束、计数一致、去重成功以及所需字段齐全等证据，才能支持相应范围的完整性。未显示某字段不等于字段不存在，读不到某卡不等于没有该卡。

模型需要表达业务意义，例如“库存实例属于某个卡版本”“提交挑战会消耗已放入的实例”。DOM 区域和选择器可以作为有版本限制的定位线索，执行时重新核对。通用浏览器执行器不应写入“重大比赛”的选择器、关卡规则或自动运行顺序。

## 经验怎样留存并让 DSH 复用

建议第一版使用一个仓库内共享目录，以下路径均为拟建：

```text
.agents/skills/fc-web-app/
  SKILL.md                         加载入口、使用方法与适用范围
  references/application-model.json 共享应用知识，作为模型的唯一来源
  references/tool-bindings.md       语义操作与 Codex/DSH 工具的对应关系
  references/experience.md          精简成功、失败和失效记录及证据索引
```

SBC 配方按需要作为该模型的一个引用文件加入。最小证据样本与回归案例放在实际拥有该行为的测试目录；原始大快照留在本地运行产物中，模型只保存必要摘录和可追溯索引。模型文件不保存登录凭据、令牌或个人账户全量库存。

[DSH 文件系统 Skill 提供者](../../packages/skill/skill-filesystem/src/index.ts)在源码中支持项目的 `.agents/skills`，因此同一个仓库可以成为 Codex 与 DSH 的共同知识来源。接手时要在目标 DSH 会话验证实际发现和加载结果；源码支持、目录存在或监视器设计均不等于该运行实例已加载。DSH 会话位于其他项目时，需要使用其实际可访问的共享 Skill 目录或显式读取本文指定路径，不能假定任意工作区都会自动发现。

更新经验遵循一次短循环：保存动作前必要状态和预期 → 执行动作 → 读回业务结果 → 归纳有适用条件的结论 → 更新知识修订。成功一次记录为已观察案例；供另一个 Agent 在新的页面实例复验后，再标明跨 Agent 复验通过。出现反例时将对应知识标为待复验或失效，并保留反例，不能静默覆盖。

例如，历史记录报告过“点击整张 SBC 卡片误触收藏”。可将它保存为定位歧义案例；“改点标题后能稳定进入群组”需要新鲜动作与读回证据，不能仅凭建议就写成成功经验。工具返回的网页文字始终是待分析资料，不得直接成为模型指令或执行授权。

要证明 DSH 也会操作，使用一个不继承探索聊天记录的 DSH 会话，只提供模型入口、工具和新的任务实例。验证其能识别状态、选择动作、处理新鲜引用并读回结果；仅能加载 Skill 不算经验转移完成。跨工具调用的 `requestId`、恢复引用和临时控件引用不能互换。

## 当前可复用能力与证据边界

以下是本会话截至 2026-09-26 的观察，均需按其时效理解。

| 能力或材料 | 已有证据 | 尚缺什么 |
| --- | --- | --- |
| Codex 的“独立浏览器扩展” | 已实际执行 `browser_status`、`browser_tabs`、`browser_read_page`；读到 FC SBC 列表及“重大比赛”，并在同一文档内定向读取成功 | 本轮未实测 FC 点击、翻页、填阵或提交；未证明四关与库存覆盖 |
| 独立连接 | [连接模块](../../apps/chrome-extension/src/codex-browser-connection.js)有独立本地连接；[运行入口](../../apps/chrome-extension/src/assistant-runtime.js)为 Codex 与 DSH 连接复用执行器和请求日志 | 共享组件不证明所有 Host 业务策略都覆盖独立连接；同一现场试跑由一个 Agent 控制，先核对现有请求状态 |
| 通用动作工具 | 独立扩展工具声明包含点击、滚动、导航、输入、按键、截图和请求状态查询 | 工具存在不证明当前 FC 页面目标可准确操作 |
| FC 页面汇总 | [页面模型](../../apps/chrome-extension/src/fc-sbc-page-model.js)累计同文档的关卡观察和库存覆盖信息 | 仍以 SBC 为中心，缺应用级对象、动作语义与经验记录 |
| 求解与报告 | [求解器](../../apps/chrome-extension/src/fc-sbc-puzzle-solver.js)、[领域函数](../../apps/chrome-extension/src/fc-sbc-core.js)、[纵切报告](../../apps/chrome-extension/src/fc-sbc-slice-report.js)已有 WIP | 搜索池受限；化学和队评未完成真实验证；候选与最终方案尚未形成现场闭环 |
| DSH 工具 | [Browser 服务](../../packages/browser/browser/src/index.ts)与[模型工具](../../packages/browser/tool-browser/src/index.ts)提供页面操作及恢复接口 | 需检查目标 Agent 实际工具范围；独立扩展的成功不能直接算成 DSH Agent 验收 |

最近一次独立扩展只读结果为 SBC 列表页，“重大比赛”显示 0/4、约 5 天 20 小时到期；读取未报告文本或控件截断。这只代表当时已加载内容。导航栏上出现俱乐部、转会等入口，不证明其权限、内容或操作已被验证。

早期侧栏报告“4 关、313 张卡、24 个待核验候选、0 个方案”，属于用户提供的运行结果。当前源码的候选验证请求会因部分关卡没有可用候选而整体保持 blocked；接手应区分已找到的候选、待验证、搜索未覆盖和确已证明无解，不能把“方案 0”统一解释为无解。

侧栏当前默认 `page-only`，只取可见页面；`full-read` 分支与[原生化学读取](../../apps/chrome-extension/src/fc-sbc-native-chemistry.js)仍有调用 EA 内部服务的代码。独立扩展通用工具没有自动把这些 SBC 模块暴露给 Agent。读写通道打通也不代表这些模块已经迁到 DSH。

`page-only` 不能自动取得完整库存；现有内部服务批量读取会额外产生 EA 请求。采用哪个读取方式需要作为真实能力和请求成本来评估，不能因其称为只读、运行在后端或由 Agent 调用就声称没有账号风险。工具调用数不等于 EA 请求数，无法测量时应记为未知。

## Sol 的最小落地顺序

### 1. 建立稀疏模型，验证一次导航

检查当前工作树与可用工具，保留相关及无关 WIP。优先使用用户指定的“独立浏览器扩展”，重新发现在线安装和 FC 标签，取得新鲜页面身份。建立上述模型的最小文件，只填已观察的页面和对象，把未验证动作明确标注。准确进入一个 SBC 群组，读回标题、所选关卡和要求；如抓手不能区分进入与收藏，先修该通用定位问题并用最小案例验证。

本步完成标志：真实导航成功，未发生非预期收藏变化；另一位实现者能从模型和证据理解动作如何定位、成功如何确认。不要把历史标签或控件 ID 写进配方。

### 2. 读齐首个任务，形成可用卡池

Agent 逐关读取当前任务的规则、阵型、奖励和完成状态，通过页面获取所需卡牌属性及实例身份，将观察组织成计算输入。可见列表分页、虚拟滚动或卡详情确实无法可靠读取时，补最小抓手，并记录本次缺口及修复依据。

允许利用已读且可核对的卡生成可行候选；完整库存影响最优性、缺卡判断和采购决策，不能成为所有候选展示的统一门槛。字段不足、同名卡无法区分或存在保护卡歧义时，标明该候选的具体限制。

### 3. 求解并验证首个业务闭环

让 Agent 调用现有纯计算函数，按当前输入修复明确的求解和验证缺口。组合计算无需模型逐项枚举。分别报告每关候选、规则检查、化学/队评依据和整组实例冲突；有限搜索未找到结果不能标为数学无解。公共卡库用于属性参照和缺卡候选，不能代替账号库存或当下报价。

形成具体的用卡、保护范围、采购需要与预算后，依据用户当次授权执行填阵和提交；现有对话未确认本轮具体阵容及消费金额。普通切页不重复询问。先验证一关的填阵读回和业务完成，再完成授权范围内的整组；提交结果要由页面完成状态及相关卡牌变化等证据确认。

### 4. 验证经验可迁移，再优化

保存最小案例，让 DSH 的新会话用同一模型完成另一任务实例或明确划定的可逆子流程；记录实际覆盖范围。检查导航、列表、卡实例和阵容等知识是否可组合复用，不能仅复述“重大比赛”的固定答案。

全过程记录模型轮次、工具调用数、耗时、失败类别、已知的 EA 请求量及是否发生非预期变更。只对测出的瓶颈提取脚本或后端函数，例如列表读取、规则转换或候选核验；提取后沿用同样的输入证据和结果判定，比较前后成本与正确性。

## 接手约束与停止条件

- 先读[仓库架构](../architecture.md)再改 `packages/`；验证按实际改动执行[最小可信检查](../../.agents/skills/dsh-change-verification/SKILL.md)。当前任务不要求新建服务族、任务平台、全站图谱或重训练模型。
- 独立扩展动作使用新鲜的页面与控件引用。结果 unknown 时查询原请求，不盲目重放；旧 DSH 请求须在其所属通道核对，不能用独立连接查询或掩盖另一个运行的未决写入。
- 历史 `journal_capacity`、收藏状态、Goal 状态和库存数字只作为时间点证据。接手按当前用户任务及当前运行状态推进，不能把旧交接快照升级为持续授权或永久阻塞。
- 不为重载配置停止 Codex/ChatGPT 桌面应用、其 app-server 或服务当前任务的 MCP。需要扩展重载或 DSH 更新时，分别说明准备好的改动和未验证层次，按现有运行边界处理。
- 最终交付分别说明模型记录了什么、哪些动作现场验证过、哪个 Agent 已复验、首个业务闭环是否真实完成。文件存在、测试通过、工具可发现和页面已完成是不同证据。

## 旧材料的使用方式

[SBC 整体设计](2026-09-25-fc27-sbc-assistant.md)与[早期现场交接](2026-09-26-fc27-sbc-handoff.md)保留领域计算和历史案例。后续架构与落地优先级以本文的 Agent 驱动、应用模型和按瓶颈脚本化方向为准。它们不能证明当前库存、权限、报价或运行状态，也不要求先建成完整 SBC 专用后端。

[通用页面模型计划](2026-09-10-browser-page-model-generalization-plan.md)可帮助理解已有页面身份和新鲜引用机制；其历史实验预算和验收流程只属于原计划。本任务按当前用户范围推进，不继承无关实验流程。
