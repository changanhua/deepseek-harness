# Case Study — runtime-awareness

## Problem Only

让 Agent 对当前运行环境、可用工具和动态能力有足够准确的认知，同时控制 token 成本、陈旧性、权限泄露和信息噪声。

在产生 independent reconstruction evidence 前，不读取现有本地 `runtime-awareness` 设计作为答案。

## Independent Reconstruction

先提交：SEE / ACT / OWN / SURVIVE、事实 authority、freshness、scope、push/pull 边界、候选 seam、验证计划。

## Source Investigation

之后再对照当前 DSH 的 context、tool discovery、runtime inventory、dynamic Cordis 等真实机制，并阅读本地旧实现。

## Review Focus

- authoritative runtime facts 来自哪里；
- prompt summary 是否过重；
- on-demand introspection 是否存在；
- freshness/revision 如何表达；
- session/global scope 是否混淆；
- model-visible 与 operator-visible 是否被混为一谈。

## Evidence Required

- `independent_design_before_reveal`
- `review_findings`
- `redesigned_contract`
