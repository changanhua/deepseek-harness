# Challenge — Unseen DSH Design

## Goal

测试 `independent_design` 是否已经从熟悉案例迁移到未见过的中等复杂度需求。

## Rules

开始时只给需求和约束，不给参考实现，不提示应使用哪个 seam。

学习者必须先提交：

1. problem definition；
2. SEE / ACT / OWN / SURVIVE；
3. 五层映射；
4. authoritative state；
5. 至少两个候选方案；
6. 需要查证的 DSH 事实；
7. 至少一个当前官方 precedent；
8. lifecycle / recovery；
9. verification plan。

之后才能进入源码取证和 review。

## Evidence Required

- `problem_definition`
- `see_act_own_survive`
- `source_precedent`
- `alternatives_and_tradeoffs`
- `verification_plan`
- `post_review_revision`

## Exit

如果设计只在老师/模型提示具体 seam 后才成立，不算独立设计通过。
